# 讲解资产与恢复维护说明

本文面向部署和维护人员，描述本批候选版本中的正式音频存储、回收及恢复规则。当前功能和实际验收状态见 [实施记录](59-exhibition-implementation.md)，不能在尚未配套升级的旧生产镜像中直接执行新模块。

## 编辑人员处理声音任务

正式讲解生成后先试听并采用，再随路线提交审核。生成完成不等于采用或发布。普通保存、预览和已发布音频读取不调用供应商。

讲稿变化时重新制作对应段落。结果未知意味着供应商可能已经处理请求，先核对原任务，再明确决定是否重试；不能连续点击生成。已采用音频、保留历史和保留操作回执中的音频不属于自动过期对象。

未采用的 ready、failed 或 cancelled 任务默认保留至少30天。经过运维核对回收后，任务显示 `NARRATION_RETIRED`，保留原操作记录与调用次数，不允许重试旧任务；需要声音时依据当前讲稿明确创建新任务。queued、running、unknown、paused 任务始终保留，需先由有权人员处理任务状态。

## 查看容量

运行管理返回的 `narration_storage` 只提供全局容量和状态，不公开服务器路径。普通内容编辑人员无权读取全局运行信息。

| 状态 | 含义和处理 |
| --- | --- |
| ok | 使用量低于80%，正常监测 |
| warning | 实际文件使用量达到80%，提前检查保留历史、未采用音频和备份容量 |
| full | 达到硬容量上限，暂停新生成并核对可回收对象；不删除仍被使用的声音 |
| unavailable | 存储存在无法核验的文件、目录或权限问题，检查维护日志；不显示假的零使用量 |

容量核算读取真实落盘文件，包含异常退出后未写入数据库的分片和临时文件。每次供应商尝试前检查一个最大受限响应能否容纳，返回后按实际大小再次核对。磁盘不足不能通过清空数据库计数绕过。

部署默认 `NARRATION_MAX_STORAGE_BYTES=2147483648`、`NARRATION_UNADOPTED_DAYS=30`。修改硬参数须经过运行维护流程，不改变已有费用计数。音频保留天数最小7天；仍被引用的资产不受未采用保留天数影响。

## 核对并执行回收

在已验证的部署目录、匹配候选 API 镜像和服务配置下运行。以下命令是明确维护动作，普通编辑人员无需使用终端。

先生成只读计划：

```sh
docker compose exec -T api python -m app.modules.narration.maintenance
```

计划包含当前使用字节、保护的资产、拟退役任务、拟删除文件和 `sha256`。不包含讲稿、回答、供应商密钥或恢复码。确认目录符合预期，所有被当前稿件、正式内容、历史或保留回执引用的音频均不在删除列表内。

执行使用刚刚核对的完整计划 SHA 和具体维护原因：

```sh
docker compose exec -T api python -m app.modules.narration.maintenance --apply --expected-sha PLAN_SHA256 --reason "核对未采用过期讲解后释放容量"
```

`PLAN_SHA256` 是占位，必须替换为本次计划返回值。计划或文件发生变化会拒绝执行，应重新核对，不能复用旧 SHA 强行删除。回收与上传、保存、发布、备份共用资料维护锁；发生占用时稍后重新生成计划。

同目录中至少七天前的合法孤儿分片、临时文件可进入计划。未知名称、链接、设备或嵌套目录会停止检查，留给维护人员调查，不递归猜测删除。校园底图、楼层原图和其他资料不由音频维护模块处理。

## 中断后的处理

元数据更新失败时不删除任何文件。元数据已提交而文件删除中断时，任务已退役，剩余文件仍计入实际容量；重新生成计划，核对后继续清理。原任务不会恢复为排队状态，也不会重复供应商调用。

审计分别记录 `narration.gc_authorized` 和 `narration.gc_completed`。只有前者不代表文件删除成功。回收记录归因到禁用登录、无业务范围的维护身份，不冒充编辑或审核人员。

媒体及楼层原件回收继续使用原 `app.modules.upload_gc` 流程，新增历史和字幕引用已纳入保护。不要直接删除上传目录来释放容量。

## 恢复演练

恢复批次覆盖数据库、地图、楼层、媒体、字幕、正式音频与配置。脚本逐文件核对路径、SHA、大小，并核对音频清单、波形和新旧路线采用关系；历史楼层原图或历史媒体缺失也判为失败。

恢复数据库中的 queued、running、unknown 任务统一转为 paused，清除租约并增加执行版本。调用次数不清零，已完成、失败或已取消任务不被自动重放。维护人员核对来源、预算和之前供应商结果后，才由员工明确恢复操作。

恢复脚本是隔离演练，不自动切换生产。文件校验通过、实际音频读取、手机实听和最终生产切换分别留证；不能以文件存在代替实际播放验收。

## 恢复后的人员重新登记

恢复隔离会禁用旧成员、清空旧范围与专项授权，撤销旧会话、通行密钥和恢复码，并保持服务紧急停用。付费调用记录和额度不清零。不得直接恢复旧账号权限或沿用备份中的认证器。

维护人员须用备份之外的当前人员记录核对身份、角色和地点范围，在经过认证的交互式服务器控制台执行 `python -m app.modules.admin.restore_recovery`，提供 `--username`、`--expected-revision`、`--role`、所需的 `--campus-id`／`--point-id` 和 `--reason`。先用 `--help` 核对参数；临时密码只在隐藏输入中录入，不放命令行、环境变量或工单。

重新登记必须匹配最近恢复批次和成员当前版本，并形成审计。成员获得十五分钟的个人认证器重新绑定窗口，须修改临时密码并亲自验证设备；维护命令不创建业务会话，也不解除服务停用、增加预算或更改内容。此流程的自动化测试不替代真实设备恢复演练。
