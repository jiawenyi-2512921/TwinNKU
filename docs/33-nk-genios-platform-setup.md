日期：2026-09-25。依据用户提供的 NK-GeniOS 页面与 WebClient 嵌入代码编写；只对已看到的入口给出确切按钮名称，其余以平台实际表单为准。本轮代码已准备网站容器与工具接口，平台配置和真实联调仍需执行。

代码与本文件引用的插件、提示词和知识模板一并提交到GitHub的 `feat/admin-console` 分支。部署方按 [32](32-nk-genios-web-release.md) 更新网站；平台资料可直接从本分支取得。[34](34-offline-delivery.md)中的离线交付包仅作备用，不要向已更新的仓库重复应用。

## 4. 知识库怎么组织

沿用 **知识库 → 创建知识库/已有知识库 → 上传资料**，完成解析后，再到“小开”编排中的 **知识库 +** 关联。用户已验证的津南图书馆介绍可以保留，但要补核来源并处理之后导入的重复版本。

建议按维护周期分四类，平台可建四个库，也可用同库目录区分：

| 类别 | 放入内容 | 不应放入 |
| --- | --- | --- |
| 校园点位介绍 | 已发布点位名称、别名、介绍、校区、ID、版本、真实来源 | 仓库未审核初稿、后台草稿、全部开发文档 |
| 校史与文化讲解 | 校方资料支持的历史事实、人物、建筑故事；分点位整理 | 模型自由创作的年份、引语、设计寓意 |
| 楼层文字说明 | 人工核对的公开楼层/分区与公共设施说明，附对应图及版本依据 | 实拍拍摄原图、私人房间信息、OCR猜测、未经核实的通行路线 |
| 访问政策与常见问题 | 有发布单位、日期、适用对象和有效期的正式公开规定；产品使用帮助 | 过期预约截图、猜测的开放时间、未经确认的联系人号码 |

第一类优先使用仓库脚本导出：见 [32 的知识库导出步骤](32-nk-genios-web-release.md#7-知识库导出)。脚本从网站公开接口读取，避免把 `data/introductions` 初稿整包直接上传。Markdown 不被该版本支持时，将同一正文保存为 UTF-8 TXT，再按平台支持格式导入。

对于新增讲解，用 [knowledge-template.md](../data/nk-genios/knowledge-template.md) 填好实际材料后导入；模板本身不可上传。每份资料至少要有标题、校区/点位、正文、来源、核对日期与版本。一个点位一份文件，按标题/段落切分；暂不盲设未确认单位的切块数值。

**图片与知识的分工：** 已标注楼层图仍由本站展示。只上传图片不能保证问答理解正确，更不能保证房号识别准确；需要回答具体公共设施位置时，应人工整理文字与原图逐项核对。暂缺文字的地方，小开应给看图入口并说明缺资料。

“强制模式”按钮的具体语义未由现有截图确认，先保留已经跑通的检索设置，查看该版本说明后再调整。不要同时堆叠不明检索开关，导致工具查询无法执行。

## 5. 知识库最先补哪些资料

先补 8—12 个核心点位的可追溯深讲，再扩全目录。可以从图书馆、周恩来雕像、两座综合业务楼、体育馆、公共教学楼、新开湖、思源堂、秀山堂及已核实文化点位中选择。

每个点位准备：
1. 80—150 字简述：是什么、为什么值得了解。
2. 300—600 字讲解：只加入有依据的功能、历史与文化事实。
3. 3—5 条常见问答：回答与出处一一对应。
4. 对应数据库 ID、名称/别名、原始资料标题/链接、核对日期。
5. 已发布楼层/VR由插件实时查，不手工复制大量将来易过期的链接。

开放时段、入校条件、研学预约规则没有有效正式资料就先不补成确定答案。对“缺资料”的正确回应本身也是需要评测的能力。

## 6. 导入只读校园插件

先完成网站 API 更新，再进入 **插件 → 自定义插件 → 导入插件 → OpenAPI 导入**。

1. 从 GitHub 打开 [nk-genios.openapi.json](../contracts/nk-genios.openapi.json)，使用下载原始文件功能保存为 `.json`。不要把 GitHub 网页另存为 JSON。
2. 在平台本地上传此文件。本轮文件约 29 KB，低于你实测的单文件 2 MiB 限制。默认文件使用 OpenAPI 3.0.3；同时提供 [3.1 文件](../contracts/nk-genios.openapi-3.1.json)，根据导入器实际支持选择，不同时安装成重复插件。
3. 插件名可填“TwinNKU校园公开资料”，描述填“只读查询已公开校园点位、楼层、全景及查看入口”。
4. 服务器地址应为 `https://2512921.cn`。本版接口查询公开资料，选择无鉴权；学校平台的 JWT、WebSDK appKey 和管理员账号都不要填到该插件认证栏。
5. 核对下面六个工具，再逐个调试。平台如要求保存/发布，按实际流程完成。
6. 返回 **Agent → 小开 → 插件 +**，选中同空间的该插件及所需工具，保存后在预览里验证调用。

| 工具 | 请求 | 如何测试 |
| --- | --- | --- |
| listCampuses | GET `/api/v1/campuses` | 取得真实校区 ID |
| listPoints | GET `/api/v1/campuses/{campus_id}/points` | q 填“图书馆”；用返回的点位 ID 继续 |
| getPoint | GET `/api/v1/points/{point_id}` | 核对名称、介绍、版本 |
| listFloors | GET `/api/v1/points/{point_id}/floors` | 核对实际公开楼层；空列表也是合法结果 |
| listPointPanoramas | GET `/api/v1/points/{point_id}/panoramas` | 核对已审核全景；不要为测试捏造结果 |
| getGuidePoint | GET `/api/v1/guide/points/{point_id}` | 核对 links 中的地图、楼层分区及全景入口 |

未知 ID 从工具查；不要照抄别的环境的 UUID。返回 404 先检查实际部署版本、ID与发布状态，不能把假的 200 样例当调试成功。

工具协议由 [生成脚本](../scripts/export_nk_genios_plugin.py) 从完整契约裁剪，不能上传整个 `contracts/openapi.json`：里面包含后台和尚未实现的未来接口。导入文件不需要填本次 appKey。

平台预览依次发送：“查一下津南图书馆”“它有哪些楼层图”“给我查看入口”。查看实际工具日志：不能仅看到自然语言提到“查询”就判调用成功。

## 7. 网页业务变量

在编排的 **记忆 → 变量 +** 中建立以下变量。全部按字符串配置，默认空字符串；数字版本也按字符串传入，避免平台类型不一致。

| 变量 key | 显示名 | 含义 |
| --- | --- | --- |
| campus_id | 当前校区ID | 当前公开校区的真实 ID |
| campus_name | 当前校区名称 | 当前校区完整名称 |
| point_id | 当前点位ID | 当前选择点位的真实 UUID；未选为空 |
| point_name | 当前点位名称 | 当前选择点位名称 |
| point_revision | 当前点位版本 | 已读取的点位版本 |
| map_id | 当前地图ID | 当前公开地图 UUID |
| map_revision | 当前地图版本 | 当前地图版本 |
| floor_id | 当前楼层ID | 从楼层页“问小开”进入时的楼层 UUID |
| floor_label | 当前楼层名称 | 如平台接口真实返回的一层、二层等 |
| floor_section | 当前楼层分区 | 如 main/a/b/c，必须对应真实分区 |

不要修改平台自带 SYS_USERID 等系统变量。本站不发送这些系统身份字段，也不把实际用户身份写入上述业务变量。

建好变量后，将 [context-instructions.md](../data/nk-genios/context-instructions.md) 追加到系统提示词末尾。若平台没有把 `{{变量名}}` 自动解析，应使用你截图左下角的 **{变量值}** 入口插入同名变量，再检查预览，不能让模型把未解析花括号当当前地点。

保存/发布后，按部署文档开启 `NK_GENIOS_WEB_CONTEXT_ENABLED=true`。再分别从图书馆与体育馆的详情入口提问“这里是什么”；从楼层页进入问“这里有哪张图”。检查实际变量和工具入参是否对应，不要只看回答是否凑巧正确。

**本轮上下文是初始化快照。** 地图点击不会静默清空对话；当前对话地点与地图选择不同时，网站会显示切换提示。点击“切换讲解地点并重载”后才把新快照交给 SDK。平台若复用历史会话，用户本轮明确地点应优先，不能以重载为证宣称开启了新会话。

## 8. 问答库、术语库与其他模块

问答库适合维护“怎么查看楼层图”“全景在哪里打开”“为什么某些地点没资料”“如何反馈错误”等稳定产品帮助。政策类问答必须记录有效来源；问答库命中可能直接返回答案，过期内容尤其需要及时替换。

术语库可录入从真实点位 aliases 核对过的简称，例如业务西楼与完整建筑名称的对应关系；校区和不同场馆不要合并成同义词。输入术语要与公开数据库一致，不能只在术语库另建一套名字。

工作流、Skills、MCP、子智能体、触发器不是本版必需依赖。当前选择 OpenAPI 只读插件已经具备查询路径；更多入口要按实际任务收益再接，避免同一问题触发重复工具。

平台内容审查与高级审查根据实际配置项和学校要求设置，保留正常反馈/批评场景测试。没有看到具体策略前，不把截图中的开关解释成已完成全部审核要求。

## 9. 发布与网站嵌入

进入 **发布配置**，检查“小开”当前发布渠道和状态。嵌入网站域名使用真实网站；主域名与 www 若都实际使用，应分别按平台规则配置。不要为图省事使用通配域名。

本次网站使用你提供的“全页面” `WebClient` 脚本，放在本站自有聊天面板内；网站代码已经包含初始化流程，不要再手工向 `index.html` 插入第二份脚本。平台生成的 appKey 填服务器 `.env`，不填写到提示词、知识库或校园查询插件中。

每次修改提示词、插件、知识库关联、变量或发布渠道后，按平台实际按钮保存/发布，再用网站新打开的窗口复测。编辑预览生效不代表已发布版本同步。

无痕/外网访问必须测试：是否要求校园统一身份、登录是否能在嵌入窗口完成、不同用户会话是否隔离。平台管理员的登录方式与最终访客访问策略可能不同，本轮没有替你改变平台权限。

## 10. 100 题评测如何使用

[evaluation-100.jsonl](../data/nk-genios/evaluation-100.jsonl) 是 **100 道未执行草案**，不是答对100题的结果。包含48道点位/楼层/全景/来源题、16道准确性与缺资料题、12道上下文题、12道工具/异常题、12道边界与正常反馈题。

1. 资料负责人先补每题 `reference_materials`：实际文档/版本、允许的事实与资源。没有参考依据的事实题标“证据不足”，不要让大模型凭常识生成标准答案。
2. 到 **评测集** 查看该版本导入模板；把单轮题的 input 和预期检查项映射到其实际字段。尚未取得该页表单，不能保证本 JSONL 可无调整直接导入。
3. 多轮题逐轮发问并保存完整会话、变量和日志；不能把“第1轮/第2轮”文本一次提交后声称通过多轮测试。
4. 到 **评估器** 按平台支持方式配置规则或人工评分；可参考 [evaluator-prompt.md](../data/nk-genios/evaluator-prompt.md)。模型评分只做辅助，事实与来源仍需人工复核。
5. 到 **评测任务** 选定智能体已发布版本、对应评测集和评估器；固定模型/提示词/资料版本，运行后记录实际结果。
6. 记录错误类别、工具日志、引用依据、耗时和修复版本。同一道题修复后复测；不要只展示成功案例。

建议内部放行条件：演示关键流程全通过；政策、来源、隐私和权限方面无阻断性错误；事实题、链接题和上下文题分别统计分子/分母。此处是项目质量目标，不是比赛官方评分标准。
