# 地图、楼层、VR与内容资料建设细则

对应CNT/RES。目标是建立准确的空间与内容资源关系，而非把每个VR视角都新增为建筑。

## 1. 交付文件的明确范围

- 当前素材只交付有标注校园规划图和已标注楼层图。实拍对照照片、无标注楼层图不进入应用资源包。
- 原图文件不降分辨率、不重编码覆盖；生成缩略图或瓦片必须作为单独衍生资产，记录来源hash、生成参数和关系。
- 程序文件/规范经GitHub分支和PR传递，大资源经Release+SHA256+清单传递；生产用户上传进入持久卷和审核流程，不能把GitHub当在线可变数据库。
- 现有服务器点位几何属于用户已修正数据。升级介绍/UI/楼层时不重新导入旧校园地图，不运行覆盖式seed。

## 2. 素材目录与不可变版本

逻辑：campus→point→floor→section→image revision；VR scene可关联多个point/floor。

每张图片最小登记字段：asset_id、原文件名（后台）、安全存储名、mime、size_bytes、width_px、height_px、sha256、uploaded_by、source_note、visibility、review_state、created_at。公开DTO不包含内部存储路径、上传者私人信息。

当前楼层规范：label是人读名称，ordinal负责排序（地下层为负数）；不得按字符串排序让10层排在2层前；section为main/a/b/c等受限slug，section_label为“东区”等中文名。分区不是独立楼层；同层只有labeled供公众读取。

上传校验：服务端读取实际文件类型，检测尺寸/像素/体积限额、异常多帧、解码失败；限制临时存储；拒绝SVG脚本、伪后缀和路径穿越。允许的PNG/JPEG须保持原字节；EXIF若发现不应公开的信息，转人工确认并单独产生脱敏版本，不偷偷重编码标为原图。当前实现限额以18/配置为准，新限额需同步前后端及代理。

## 3. 地图点位维护

| 操作 | 规则 | 结果验证 |
| --- | --- | --- |
| 移动锚点 | 使用原图像素，是否连同多边形移动明确 | 不越界，不缩放底图 |
| 调整轮廓 | 至少3点、非退化、不自交、坐标合法 | 点击命中，不吞掉更小分区 |
| 改名/别名 | 保持UUID，已烧录图中文字无法仅靠数据擦除 | 详情/检索更新；图内旧字另行计划素材版本 |
| 新增地点 | 有核实名称/位置/公开资料，独立审核 | 未命名建筑不默认自动生成点击 |
| 下架 | 软撤回，关联楼层/VR不泄漏 | 地图、列表、直链、AI动作均停止可用 |
| 更换底图 | 新map revision；坐标变换人工核验 | 不能直接套用旧轮廓和路线 |

周恩来雕像按正式后台坐标维护；之前撤销的张伯苓雕像、严范孙雕像、学生文化谷不得从历史材料自动恢复。前沿交叉学科中心已有开发完成信息，介绍不得保留“施工中”作为当前状态。

## 4. VR场景盘点台账

官方VR数量可能远大于83个地点，这是正常的资源粒度差异。先获取官方提供的分享地址和场景列表；不尝试绕过站点权限或抓取非公开全景原始文件。

建议台账字段（CSV/后台均可，导入前校验）：

| 字段 | 必填 | 含义/格式 |
| --- | --- | --- |
| intake_id | 是 | 本次整理稳定编号，仅后台使用，不显示满图编号 |
| official_title | 是 | 官方原场景标题，不凭画面随意命名 |
| display_title | 是 | 访客易懂的“图书馆·外观”等标题 |
| campus_id | 是 | 未核实校区进入待核实，不默认津南 |
| source_url | 是 | 证明来源的官方页 |
| scene_url | 是（发布时） | 能直达对应场景的HTTPS分享URL |
| provider/scene_key | 有则填 | 真实平台标识，不能靠猜测参数构造 |
| primary_point_id | 可空 | 主地点UUID；无定位场景可先无关联 |
| other_point_ids | 可空 | 同画面可见相关地点，人工核对 |
| floor_id/section | 可空 | 确实在楼内且能定位才填写 |
| description | 是 | 可看到什么，不添未核实历史故事 |
| link_mode | 是 | external或获准embed；首版external |
| sort_order | 是 | 点位详情/主题内的稳定顺序 |
| reviewed_by/at | 发布时 | 独立审核人与时间 |
| checked_at/status | 是 | unknown/available/failed/recheck，观察时间 |
| authorization_note | 是 | 可引用依据、公开范围，不虚构授权 |
| mobile_checked | 发布时 | 手机实测结果/日期 |

URL规范化需保留有语义的query/hash，如scene ID和视角；只删除经证实的跟踪参数。不能仅hostname相同就认定同场景。封面截图需明确使用许可和来源，且不能把图库封面当全景已接入证据。

## 5. 从台账到应用的分批策略

第一批20—30个精选场景覆盖8—12个核心内容点，数量为目标：先选择能稳定直达、与讲解相关、校区正确、手机能打开的场景。每批5—10个，编辑→预览→独立审核→公开点击验证。

关联判定：

1. 同建筑不同外观/门厅/楼层视角：同point下多个场景。
2. 湖泊/广场/雕像：用已有景观point；确有新增核实地点再建point。
3. 同一全景看见多栋楼：一个scene、多条关联；主关联用于默认排序。
4. 另一校区：进入独立待整理列表，等待对应地图上线；禁止硬投津南。
5. 无法定位：可在未来独立“全景探索”目录展示已审核场景，map anchor可缺省。
6. 不能稳定直达某场景：只给“官方VR入口”，不能标题说直达图书馆却打开任意首页。

目前后台是每点多链接，已经能完成第一批建设；独立scene与多对多迁移属于P1。不要为等全量scene系统而停止核实可直接使用的内容。

## 6. 外部链接与嵌入边界

HTTPS、无用户名密码、来源域名明确。服务端不抓用户输入的任意URL、不开放VR代理，以免形成SSRF。首版外链使用noopener/noreferrer，用户手势打开；第三方限制iframe时保持外链，不绕过CSP/X-Frame-Options。

未来嵌入须核实：允许域、iframe能力、移动端交互、资源公开范围、允许的postMessage来源与schema。不能监听或读取跨站DOM。即使iframe发“scene changed”，也只接受来自白名单origin和合法scene ID的信息。

外部VR不受本系统撤销访问令牌控制；应用下架只移除入口。已公开图片不能绝对阻止截图/保存；权限控制、脱敏、来源记录和有效期是可实际兑现的要求。

## 7. 20栋楼层导入与更新验收

使用17所述完整Release包和SHA256；入库前比较20栋/96层/100张清单。不同阶段独立记录：收到文件→字节校验→导入→数据库已发布→HTTP原图可读→手机实际查看。任何一项不能代替另一项。

每栋至少检查：建筑名称及UUID、层数、地上地下排序、同层分区、照片/无标注图排除、分辨率/hash、图中文字可读、建筑点击路径、链接跨层恢复、审核来源。全量自动检查100个资源的字节一致性，人工抽查不能替代hash全检。

后台补新图：选建筑→新增楼层或新revision→上传标注图→记录来源→预览1:1→保存草稿→他人审核→发布→公共链接复核。替换图不复用旧revision URL；“提交审核”不等于“公开显示”。

## 8. 介绍与深度内容生产模板

基础点位卡：正式名称、别名、类型、当前可确认用途、与校园关系、可看资源、来源、核对日期、开放信息未知说明。基础描述不把“可能/应该”转换成确定事实。

核心点深讲：

- 标题与一句核心问题（如这座建筑与哪段办学历史有关）。
- 60—120字快速认识；300—600字主讲；按需展开深度材料。
- 3—5条事实，每条source/version/证据摘录；数字/人名/年份单独核对。
- 一个观察任务，明确关联哪张图或VR；没有图像证据就不说“你现在可以看到”。
- 一个思考问题与教师提示；开放题不声称唯一答案。
- 参观政策另列有效期和官方渠道，不能埋在永久历史介绍里。
- 可选音频/译稿均绑定同一内容版本，审核后才能发布。

摘要2000字符上限是当前DTO约束，不可通过拼巨大Markdown突破。需要长讲解时新增Narration/point_content结构，保留summary兼容。

## 9. 内容质检与台账状态

intake→needs_verification→draft→in_review→published→retired；失败记录原因而不删除素材证据。质检包括同名异地、旧名新名、年份混淆、图上不对应、跨楼层链接、分区错位、来源失效、对公众可见性。

发布包必须附：输入文件清单、排除清单、SHA256、建筑/点位映射表、审核人、版本、已知缺口、回退方式。示例或待核实条目不能填充为“已经上线100%覆盖”。
