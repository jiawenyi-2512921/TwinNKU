## 1. 最终产品定义

面向社会公众、校友与研学团体的**有依据、能操作地图与场景、可持续审核更新的校园文化智能导览**。主入口是网页；官网与公众号可链接/嵌入网页和接入同一后端能力，首发不建设小程序。项目服务宣传部，核心价值为降低重复咨询、扩大线上参观覆盖、把分散校史文化资料转为连续可理解的体验。

一句话用户价值：用户说明兴趣与时间，系统从获准公开的校园资料中组织参观，能回答、定位、打开楼层/VR、保持进度，并给出有依据的参观回顾。工作人员能定位资料缺口，补充、审核，再验证新的答案。

评价作品的四个支柱：事实与口径可靠；操作连贯且易用；学习体验有价值；管理和运行可维护。精美界面、模型回答长度、点位数量和技术名词均不能替代这四项。

## 3. 人群、场景与成功定义

| 人群 | 具体任务 | 系统应做到 | 不做的错误承诺 |
| --- | --- | --- | --- |
| 首次访问公众 | 不知道校园有什么，想先看一眼 | 看图找点，理解核心故事，进入可用VR | 浏览网页不等于获得入校许可 |
| 校友 | 了解特定学院/地点的新旧变化 | 别名搜索、历史与当前事实分开、来源日期 | 不把历史事件写成现址发生 |
| 研学组织者 | 准备一个20分钟线上主题 | 目标、站点、问题、回顾可复用 | 不自动审批团体参观申请 |
| 学生/教师 | 围绕校史与学科提问 | 难度可选、追问保持上下文、知识有出处 | 不依据随意问答作高风险评价 |
| 宣传编辑 | 修正地点、楼层、VR、讲解 | 预览、草稿、差异、提交、退回后继续编辑 | 编辑不能绕过独立审核 |
| 审核人 | 核查口径与公开范围 | 看原始来源和差异，一次变更的贡献者不可自审 | 管理员角色不豁免自审限制 |
| 运维 | 升级、备份、排障 | 版本明确、错误可定位、模块可降级 | 不能用删卷重建“修复”生产 |

## 4. 项目范围与分期

| 阶段 | 必须完成 | 扩展条件 |
| --- | --- | --- |
| R0基础可用 | 地图、点位、楼层、VR入口、审核、介绍、精简UI稳定 | 资料和界面逐项通过 |
| R1智能导览核心（P0） | 真实NK-GeniOS调用；有来源问答；定位/楼层/VR动作；一条旗舰主题；可取消可恢复 | 外部协议与审核资料齐全 |
| R2比赛增强（P1） | 8—12个深度点位、3条主题、20—30精选VR、回顾、咨询缺口闭环、真实试用 | 先保证R1稳定，不以新增功能挤占修复 |
| R3常态运营（P2） | 官方渠道接入、SSO、权限扩展、音频、多语言、教师任务单、多校区 | 有负责人、授权素材、维护流程与成本预算 |
| R4探索（P3） | 局部室内路线、今昔对照、选择性三维场景 | 明确需求和实测数据；不作为当前必交 |

全校3D重建、实时室内定位、无数据的精确步行导航、自动人脸识别和强制虚拟人物播报不进入冲刺主路径。公开图片一旦到达浏览器无法保证不能截图；“受控”指来源/发布/权限/访问过程可控，不能宣称绝对防复制。

## 6. 高要求的硬性发布门槛

- 代码、接口、文档、数据库和公开能力状态一致；计划接口不得出现在生产路由。
- 关键事实、来源、人物日期、政策表达、跨校区归属经人工核对；事实错误优先于动画缺陷修复。
- 权限、自审、草稿泄漏、越权原图读取、动作执行边界测试零失败。
- 公开AI能力必须有真实平台调用；平台不可用时明确失败，地图与资料保持可用。
- 对外宣传数据都能追溯原始测试；没有测得的数据写“目标/待测”。
- 手机和电脑都能完成找点→看资料→楼层/VR→返回；没有横向溢出、关键按钮遮挡和不可退出状态。
- 任何迁移都说明备份与回退；禁止重新灌旧地图覆盖正式数据。

## 7. 范围变更制度

新需求先写：目标用户问题、现有不足、方案、涉及数据/接口/权限、素材依赖、验收、回退、优先级、替换哪项工作。P0未通过前不同时开启多个P2。请求“更顶尖”不能成为反复替换技术栈的理由；只有真实测试表明约束无法满足才开ADR更换组件。

变更状态：proposed → accepted → contract_ready → in_progress → verified → released；blocked必须有具体依赖、负责人和下一核验时间。验收者不能以“页面能打开”替代全任务验证。
