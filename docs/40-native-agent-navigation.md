# 小开主服务接入、网站动作与导航部署

2026-09-28。用户报告旧独立演示问答已经跑通，本批把这条协议接入主 FastAPI / React，并增加道路管理、审核、路径计算与高亮。用户此前的成功不等于本批新版本已部署。

## 本批范围

- 前端原生聊天替代演示 iframe；服务端保管学校 API 密钥，浏览器使用独立访客 Cookie 和 CSRF。
- 普通整站部署会同时构建新问答功能，无须重新挂演示 Nginx 文件。旧 companion 继续保留供回退。
- 小开返回定位、楼层、VR、路线候选；服务端核验公开状态、归属和版本，点击时再核验。前端只使用校验后的资源 ID，不执行模型 URL 或代码。
- 单个明确的定位、楼层或导航动作可自动应用；VR、多个选择、过期上下文采用用户点击。管理员可关闭自动动作或某类动作。
- 导航先明确起终点。当前浏览点不是 GPS；只有用户明确“从这里”才按当前浏览点作为出发选择。暂无已核实路网时只定位终点并说明缺口，不画直线冒充道路。
- 后台管理路网、路口、转折点、建筑入口、道路方向、关闭状态、无台阶属性、核实依据和实测长度。独立审核发布、草稿试算、运行设置和审计一并提供，见 [41 后台操作](41-road-and-guide-management.md)。

本批没有上传实际校园路网，也没有自动审核生产数据。路网算法测试使用明确标注的合成夹具；它们不会进入生产地图。

4. 使用当前正常运行的 Compose 项目名和原 `.env`。不要 `down -v`、重导旧地图或重建资料。

```bash
cd /root/TwinNKU
git fetch origin
git switch feat/admin-console
git pull --ff-only origin feat/admin-console
```

## 沿用已经跑通的演示凭据

默认原演示状态目录为 `/opt/twinnku-agent-demo`。脚本只读取原 `demo.env`，将应用 API 密钥与访问口令写入主项目私有 `.env`，不打印值、不连接学校、不重启服务。原 `.env` 以600权限备份，原演示目录保持不变；若主服务已配置不同凭据，拒绝覆盖。

```bash
sudo python3 scripts/adopt_agent_demo.py \
  --project-root /root/TwinNKU \
  --state-dir /opt/twinnku-agent-demo
chmod 600 .env
bash scripts/deploy.sh
```

脚本会配置：`NK_GENIOS_API_ENABLED=true`、`NK_GENIOS_API_KEY`、`AGENT_ACCESS_CODE`。这些只进入 API 容器环境；不得运行并公开粘贴完整的 `docker compose config`、环境或密钥内容。

如果从未安装旧演示，在服务器本地私有编辑器中设置上述三项；访问口令至少16位。`PUBLIC_SITE_ORIGIN` 必须与浏览器 HTTPS 来源一致，包括是否带 www。原 `NK_GENIOS_WEB_*` 字段可保留，后端 API 启用时原生界面优先。

普通部署重建 web 后，旧 `/agent-demo/*` 入口可能不再由 Nginx 代理；这是正常切换。新接口为 `/api/v1/agent/*`，不要再用旧 `/agent-demo/health` 作为新版本验收依据。

## 先验收问答与动作

1. 浏览器硬刷新，打开“问小开”，应看到网站原生输入框；使用原访问口令登录。
2. “帮我定位图书馆”：核对地图地点正确。单个明确动作可自动定位；回答仍保留在聊天内可回看。
3. “查看图书馆二层楼层图”：必须打开已发布的正确楼层/分区；缺资料就说明，不能猜图。
4. “打开图书馆全景”：展示已发布全景按钮，由用户点击打开。多个场景应供选择。
5. 发问后手动切换地点，旧回答不得自动拉回；原按钮仍可手动重新选择，但会再核对版本。
6. 隐私窗口建立第二会话，连续追问核对隔离；服务重启后应提示重新建立会话。
7. 学校服务出错时保留真实错误与问题文字，地图、楼层和独立导航继续可用；不自动重发不确定的请求。

平台按请求中的 JSON 约定返回结构化动作时，网站支持完整动作解析；返回普通文字时，明确命名的定位、起终点、VR、楼层请求使用公开资源确定性解析作为补充。复杂语义仍需在学校应用实测，代码测试不等于模型遵守格式。

本站系统提示与目录是在每轮调用中补充的应用协议。NK-GeniOS知识库和平台配置仍由学校平台管理；不得通过浏览器共享个人登录 Cookie。官网已发布资料可继续用原知识导出脚本同步，未审核草稿不进知识库。

## 再验收导航

按41在后台完成一段真实道路样板：两个建筑的实际入口、中间路口与转折点、连接道路、通行核验、独立审核。

- 先点击“路线导航”选择A和B：显示沿已发布道路的连续高亮，起终点标在入口。
- 再问“从A到B怎么走”：使用同一计算接口与路网，结果应与手动选择一致。
- 只问“我要去B”：定位B并打开起点选择，不猜当前所在地。
- 封闭其中一条路，审核发布：当前路线应在30秒内或窗口重新聚焦时失效；重新计算绕行或明确不可达。
- 草稿修改不影响已发布路线；旧地图版本、已下架地点、未知无台阶属性不产生伪路线。
- 没有实测长度时距离为null，不显示米数与步行分钟。部分长度已测量时不会混用米和像素权重选路。

当前仅室外、两个地点之间的道路导航，支持建筑多入口择路；无实时定位、室内跨层、途经点、多校区连接或自动时段调度。临时通行状态由后台维护。

## 运行边界

- 学校 HTTP 协议来自先前确认的文档：create_conversation / chat_query_v2，阻塞式回答，无 Cookie 和重定向跟随。
- 每进程最多4个同时调用、64个活跃访客会话，默认每访客每小时30问、全站120问；小时额度可在后台修改。学校自身额度可能更低。
- 当前单 API 进程运行；会话和幂等记录在内存中，重启后需要新建会话。不要直接配置多个 Uvicorn worker 或多个 API 副本。持久会话、原生流式和跨进程队列属于后续工作。
- Cookie为HttpOnly/Secure/SameSite，写请求核验Origin和CSRF；主页面只收文字与受控资源动作，不渲染模型HTML。
- “本次提供给小开的地点资料”表示实际输入材料，不宣称每一句已自动事实核验。学校真实回答的准确性、时延、格式和手机操作需单独验证。
- 后台运行开关只影响已经实现的能力。密钥、域名、数据库连接仍使用服务器配置；不提供在后台执行任意脚本的入口。
