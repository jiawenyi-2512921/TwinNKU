# 随行语音、校园媒体、打卡与定制导览

2026-09-29。本批接续用户已验收的导航，增加持续保留的小开浮窗、公开资源目录联动、地图选起终点，以及经过审核的媒体、打卡推荐与定制导览。本文说明代码实现和部署验收要求，不代表服务器已经升级或手机语音已经通过实测。最终提交、CI和测试结果以根目录 `VALIDATION.md` 为准。

## 访客实际体验

- 小开打开地点、楼层或导航后缩为小浮窗，保留本次聊天；点击“文字交流与记录”展开输入和消息。关闭浮窗会暂停语音。
- 点击麦克风授权后，说完一句自动发送；取得学校应用的文字回答后由浏览器朗读，朗读结束再开始听。识别中显示字幕，回答与资料入口可回看；朗读时可中断并继续说话。
- 这是 **浏览器 Web Speech 识别/朗读 + 学校文字问答的轮流对话**，不是已经接通学校的实时音频流或全双工通话。浏览器可能使用自身在线语音服务；权限拒绝、服务不可用、后台切换或网络错误会暂停，仍可使用文字。
- 每轮问题附带当前地图已发布的地点、楼层、VR及体验目录。明确的楼层/分区、全景、打卡、视频和主题请求按公开目录匹配；多个结果供选择。它能打开已标注楼层图，但没有宣称识别图中全部房间或实现室内导航。
- 视频先显示观看邀请，用户打开播放器后再按播放。外部视频页面在新窗口打开；MP4/WebM直链和上传视频可使用站内播放器，实际兼容性取决于浏览器和提供方。视频播放时暂停语音，结束后用户可点麦克风恢复。
- 导航可用“地图选起点 / 地图选终点”，只接受当前已审核路网存在可用入口的地点；地图高亮帮助选择。自由浏览地点不被当作GPS定位。原加减缩放工具栏移除，地图仍可拖动、滚轮和双指缩放。

助手动作仍经过服务端核验：公开状态、地图版本、地点归属、资料版本和管理员动作白名单。点击旧回答会重新核验；模型返回的任意URL、坐标和代码都不直接执行。

## 后台整理内容

打开“媒体、打卡与路线”。所有内容填写主地点、标题、介绍和来源/公开依据；先保存草稿，提交另一位审核者。上传成功只产生私有待审文件，不等于公开发布。

| 类型 | 编辑内容 | 使用方式 |
| --- | --- | --- |
| 图片与视频 | 图片/视频类型；本地文件或公共HTTPS链接二选一；标题、介绍、来源 | 审核发布后出现在所属地点；视频可由小开询问是否观看 |
| 打卡点 | 关联已有地图地点，填写说明，可选择同地点已发布的图片作为样图 | 展示地点与参考图；访客可自行确认打卡 |
| 定制路线 | 主地点、总介绍、顺序站点、每站讲解、同地点已发布的视频及询问时机 | 逐站浏览、查看地图、选择相邻两站导航，保存与恢复进度 |

建议先发布图片/视频，再创建引用它们的打卡点或路线。不会自动生成学校素材，也不会把未审核介绍加入公开目录。

路线每站的视频时机：

- **打开本站时**：切到该站后显示观看邀请，不自动播放。
- **访客确认读完介绍后**：用户点击“我已阅读本站介绍”后显示邀请。
- **访客主动选择视频时**：先点“查看本站视频”，再决定播放。

路线最多50站。所有站点属于同一校区，并且全部在操作员授权范围内；发布前涉及的地点必须公开。路线表达参观顺序；“从上一站导航到本站”调用现有已审核路网，不能用站点连线代替步行路径。没有GPS到达判定、视频定时自动播放、行程优化器或跨层室内路线。

访客确认、跳过、暂停与恢复进度只存在本浏览器；路线发布版本变化后重新开始。打卡也是访客本人确认的本地记录，不是定位核验或官方签到。浏览器禁止存储时会提示记录仅在当前页面保留。

## 审核、撤回与失效处理

- 编辑员/管理员可编辑、提交；审核员/管理员可审核。上传者、编辑参与者和提交者均不得审核自己的本次修改。
- 修改草稿不影响当前公开版本。保存和审核必须带当前revision；发生冲突应重新加载，不覆盖他人变更。
- “申请下架”直接进入待审。独立审核通过后隐藏内容；可通过新草稿重新核对和发布恢复。
- 作用域按后端强制执行；路线读取、编辑和审核同时检查所有站点，包括仍公开的旧版本。
- 引用图片/视频或任一关联地点下架后，引用它的打卡或路线也停止公开；旧助手动作不能继续打开。重新发布相关内容后按当前状态重新核验。
- 本地媒体每次请求都检查当前公开状态，包括视频Range请求，使用`Cache-Control: no-store`。已经送达设备的字节无法远程收回；第三方外链访问也不由本站撤销。
- 操作写入`experience.*`审计。没有硬删除、批量自动审核或自动导入生产素材。

## 接口与存储

运行DTO位于 `apps/api/app/modules/experiences.py`，机器契约与前端类型按原流程生成；完整字段见 [31 接口参考](31-api-reference.md)。

| 接口 | 用途 |
| --- | --- |
| `GET /api/v1/experiences` | 公开目录，可按`campus_id`、`point_id`、`kind`筛选 |
| `GET /api/v1/experiences/{id}` | 重新核验的公开内容 |
| `GET /api/v1/experiences/{id}/media` | 已发布本地媒体，支持单段/后缀等HTTP Range请求 |
| `GET/POST /api/v1/admin/experiences` | 授权范围内列表/新建草稿；列表支持类型、状态、地点、校区和文字搜索 |
| `GET/PUT /api/v1/admin/experiences/{id}` | 详情/保存草稿，校验草稿及发布版本 |
| `POST /api/v1/admin/experiences/{id}/review/{submit,publish,reject,discard}` | 提交、审核发布、退回、撤回 |
| `POST /api/v1/admin/experiences/{id}/retire` | 发起独立下架审核 |
| `POST /api/v1/admin/points/{point_id}/experience-media` | 原始文件请求体上传，非multipart；沿用后台Cookie、Origin、CSRF |
| `GET /api/v1/admin/experience-media/{upload_id}` | 仅授权员工可预览的上传文件 |

内容类型为`media`、`checkin`、`tour`。公开响应为`{id, revision, content, media_url}`；托管文件返回本站受控地址，外链返回已审核的HTTPS地址。助手查询复用同一公开状态检查。

上传支持`image/jpeg`、`image/png`、`video/mp4`、`video/webm`，单文件上限 **100MiB**。图片检查实际类型、完整解码及像素限制；视频检查文件头、容器、视频轨与时长，使用`ffprobe`限定本地文件协议、容器及15秒校验时限。MP4支持H.264/HEVC/AV1，WebM支持VP8/VP9/AV1；通过容器校验不代表所有浏览器都能解码该编码。没有自动转码；优先准备目标手机已验证可播的MP4。

文件保存在`FLOOR_ASSETS_DIR/.experience-media/{upload_id}/original.*`；当前Compose对应`floor_assets`卷的`/data/floors/.experience-media`。保留原始上传字节，数据库记录归属、上传者、大小和SHA256。备份需覆盖数据库与整个`floor_assets`卷；不要把该目录映射为绕开审核的静态公开目录。

外链必须公共HTTPS，不允许明文HTTP、账号密码、私有地址或自定义端口。服务器不抓取、转码或代理第三方链接；页面是否允许嵌入、直链是否过期、版权和公开授权须由内容人员核对。

## 本次部署要求

本节供用户/部署助手执行，本轮代码开发没有执行生产迁移或自动上线。

1. 记录当前Git SHA、镜像和配置；备份数据库、地图卷及楼层/媒体卷。使用现有Compose项目与服务器私有`.env`，等待最终完整提交CI通过后更新`feat/admin-console`。
2. **同时重建API和web**。迁移head为 **`0007_experiences`**，新增`experiences`和`experience_uploads`，不重导地图、楼层、点位、路网或校园内容。
3. `deploy/api.Dockerfile`新增`ffmpeg`系统包，用其中`ffprobe`检查上传视频；仅更新Python依赖不够。缺少校验组件时返回503，不接受未经校验的视频。
4. `deploy/nginx.conf`对`/api/v1/admin/points/{UUID}/experience-media`单独设置`client_max_body_size 100m`和`proxy_request_buffering off`。楼层上传保留32m，普通JSON接口保留1m。若外层还有域名反向代理/CDN，也要对同一路径允许100MiB，保持后台认证头、原始Content-Type和Range响应；不要全站扩大请求限制。
5. 更新web的CSP：本站及HTTPS图片/视频可展示，脚本仍只来自本站。该HTTPS媒体范围服务于人工审核的外链，并非媒体域名白名单；有更严格供应商范围时可在部署层收紧。外层代理若另加CSP，应与此用途相容。
6. `ALLOWED_HOSTS`包含实际访问域名以及现有内部健康检查主机；`PUBLIC_SITE_ORIGIN`和启用后台时的`ADMIN_PUBLIC_ORIGIN`均为准确的HTTPS来源。保持现有服务器密钥，不写入前端、Git或部署日志。

已运行的Compose项目可使用以下不重导资料的升级流程；在现有项目目录执行，保留原项目名及`.env`：

```bash
docker compose build api web
docker compose run --rm --no-deps migrate alembic upgrade head
docker compose up -d --no-deps api web
docker compose exec -T api alembic current
docker compose exec -T api ffprobe -version
python3 scripts/smoke.py http://127.0.0.1:8080
```

这里假定现有数据库正常运行；本机HTTP端口如有自定义则替换最后一行。显式覆盖`migrate`命令，只运行Alembic；不要为本批执行旧地图/楼层导入或生产数据种子。不要运行`down -v`。保持现有单API进程：学校会话仍在进程内，升级重启后访客需重新建立会话。

### 必须检查已有动作白名单

旧数据库可能已经保存只包含定位/楼层/VR/导航四项的`GuideSettings.allowed_actions`。升级不会擅自扩展已保存的权限。管理员在“智能导览设置”按需要勾选并保存：

- `show_checkin`：展示打卡点与样图。
- `play_video`：询问是否观看已发布视频。
- `show_tour`：打开定制校园导览。

填写变更说明。后台未发布任何新内容时，开启动作也不会产生素材。原有`FLOORS_ENABLED`、`VR_ENABLED`和问答/导航开关仍然生效；直接媒体/主题目录并不依赖学校问答服务在线。

## 真实验收顺序

1. **迁移和基础回归**：确认head为0007、就绪检查正常；地图清晰度、已发布点位、原楼层与VR仍能打开，原导航仍沿审核路网显示。
2. **跨账号审核**：编辑账号上传一张合法图片和一段真实小视频，保存后确认公开端不可见；提交者不能自审，另一审核账号发布后公开端可读。草稿修改不得提前改变公开版本。
3. **资料联动**：以真实已发布资料提问楼层、具体层数/分区、VR；未选地点时询问可参观地点。下架资料后重试旧回答按钮，应拒绝或提示更新，不能继续展示旧入口。
4. **媒体与打卡**：发布同地点样图，再发布打卡说明。手机查看样图并自行确认，刷新核对本地记录。播放视频、拖动进度、退出播放器；检查无自动播放及语音暂停。独立审核下架媒体后，旧媒体地址及引用它的打卡/路线不得继续公开。
5. **路线与地图选点**：创建两站以上路线，分别测试三种视频提示时机；开始、下一站、跳过、暂停、刷新恢复及版本更新重置。从上一站进入导航，再回到导览；地图选起终点后核对地点和可用入口。
6. **手机语音**：在实际HTTPS域名上测试iOS Safari、目标安卓浏览器与桌面Chrome；分别检查首次授权、拒绝授权、连续两轮、朗读中断、导航后继续交流、视频冲突、锁屏/后台切换和识别服务断网。记录浏览器版本与真实结果，不把Node状态机测试写成麦克风已验收。
7. **学校模型**：确认真实回答使用当前发布资料、缺资料时说明、不捏造房间/道路/播放状态；记录实际时延与错误。公开目录联动和自动测试不等于已调整学校平台知识库。

本轮没有内置假打卡样图、示范校园视频或未经核验的主题文案。首条主题需要团队提供真实内容并独立审核。真实设备语音、第三方视频兼容性、生产上传和升级后的学校问答仍需上述验收。

## 回退与停用

急需降级体验时可先关闭对应助手动作、下架问题媒体/路线，保留地图和独立导航。不要直接删除上传目录或数据库表。完整镜像回退需匹配迁移状态：应用就绪检查核对数据库head，不能只换旧API镜像而保留不匹配版本。由部署方先在隔离环境核对升级前备份及镜像，再制定恢复方案；不要在含新内容的生产库上直接执行破坏性downgrade。
