# 学校对话平台校外不可达的排查

2026-10-01，用户反馈智能体一对话就超时。本文记录排查过程、证据与结论。

## 结论

**不是本站代码或服务器故障。** 学校对话平台 `coze.nankai.edu.cn` 的 80/443/8080 端口不再响应校外请求；网络路径本身是通的。

该平台对校外的可达性**历来不稳定**，本次是学校侧访问策略变化。

## 现象

以真实契约（`code` / `request_id` / `query` / `context`）实测三次对话，每次固定约 30.7 秒后返回 503：

```
[登录] HTTP 200  0.41s
[对话] HTTP 503  耗时 30.90s  问题: 图书馆怎么走
[对话] HTTP 503  耗时 30.67s  问题: 你好
[对话] HTTP 503  耗时 30.73s  问题: 介绍一下南开大学津南校区
```

返回体：

```json
{"error": {"code": "AGENT_UPSTREAM_UNAVAILABLE",
           "message": "学校平台响应超时，结果未确认，请勿立即重复发送"}}
```

## 定位

超时点在**第一步「创建对话」**，尚未走到提问环节。该步超时设为 30 秒，与实测 30.7s 相符：

```python
result = self.upstream(
    "create_conversation",
    {"UserID": session.user, "Inputs": {}, "ConversationName": "TwinNKU guide"},
    self.key,
    30,          # ← 与实测 30.7s 吻合
)
```

上游地址（`apps/api/app/integrations/nk_api.py`）：

```python
BASE_URL = "https://coze.nankai.edu.cn/api/proxy/api/v1"
```

超时被归类为 `NETWORK_TIMEOUT`：

```python
except urllib.error.URLError as error:
    if isinstance(error.reason, (TimeoutError, socket.timeout)):
        raise ProbeError("NETWORK_TIMEOUT") from None
```

## 证据

**网络层**：DNS 正常解析；TCP 80 / 443 / 8080 全部无响应；连续 5 次重试 5/5 超时（稳定不通，非抖动）；curl 输出 `Trying <coze 地址>:443...` → `Connection timed out after 20001 milliseconds`。

**对照测试**：

| 目标 | 结果 |
| --- | --- |
| `www.nankai.edu.cn` | ✅ HTTP 200（1.1s） |
| **`coze.nankai.edu.cn`** | ❌ **超时** |
| `iam.nankai.edu.cn` | ✅ HTTP 200（0.7s） |
| `www.baidu.com` | ✅ HTTP 200（0.7s） |
| `dashscope.aliyuncs.com` | ✅ 可达（0.5s） |

同属 `*.nankai.edu.cn`，`iam` 通而 `coze` 不通 —— 排除"整个南开域名被拦"与"服务器外网出口故障"。

**路由追踪**：两个地址的探测包**均能到达末跳的校内网设备**，说明路径通畅。差异仅在端口层：`iam` 的 443 正常响应，`coze` 的 80/443/8080 全部静默。

**路径通、端口不通** ⇒ 不是路由或链路被拦，而是该服务或其端口不再接受校外访问。

## 排除清单

| 假设 | 证据 | 结论 |
| --- | --- | --- |
| 代码被改坏 | 同期只修改 `navigation_graphs` 一张表，`assistant.py` / `nk_api.py` 零改动 | 排除 |
| 密钥失效 | 用 `agent-demo` 的同一把密钥测同一接口，同样超时（密钥问题会返 401，非超时） | 排除 |
| 服务器防火墙拦截 | ufw 无任何针对南开地址的 deny/reject 规则 | 排除 |
| 服务器外网故障 | 百度、百炼网关、`iam.nankai` 均正常 | 排除 |
| 网络抖动 | 连续 5 次重试全部超时 | 排除 |
| 路由被拦 | 探测包可抵达校内网设备 | 排除 |
| **学校侧服务访问策略变更** | 路径通、端口静默；历史上时通时不通 | **确认** |

## 历史可达性

该平台对校外的可达性历来不稳定，非本次突发：

| 时间 | 状态 |
| --- | --- |
| v0.8.0 时期 | 不可达 |
| v0.9.0（09-25） | 不可达（记录原文：从服务器侧完全不可达） |
| v1.0.2（09-28） | **可达**（HTTP 302 / API 返回 400，0.83s） |
| 本次（10-01） | 不可达 |

v1.0.2 的记录已注明"学校侧的网络策略可能已调整，或者当时是临时故障"。09-28 前后为短暂可达窗口。

## 影响范围

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 智能体对话 | ❌ 不可用 | 依赖该上游 |
| 地图浏览 | ✅ 正常 | 不依赖上游 |
| 楼层 / VR / 视频 | ✅ 正常 | 不依赖上游 |
| 道路导航 | ✅ 正常 | 不依赖上游 |
| 语音合成 | ✅ 正常 | 走百炼网关，另一条链路 |
| 智能体登录 | ✅ 正常 | 仅校验收访问码，不触上游 |

## 处理建议

1. **与学校网络中心/信息化办确认**该服务是否仅限校内访问，能否将校外服务器地址加入白名单。沟通时可说明"此前可以正常调用、现在端口无响应"，该事实可排除"本不应访问"的情形。
2. **服务器接入校内网络**（VPN / 专线）。成本较高但可一劳永逸。
3. **改接公网可达的模型服务**。可立即恢复，但不再是学校平台的问答能力；若原对话挂接校内知识库，需另行迁移。
4. **暂时关闭对话入口**（`chat_enabled`）。避免用户每次等待 30 秒才获得失败提示。

## 说明

对话失败提示「结果未确认，请勿立即重复发送」是准确且有意的设计 —— 上游可能已受理请求，劝阻重复提交可避免产生重复记录。若短期无法恢复，建议在前端补充更明确的网络原因说明，减少无效重试。
