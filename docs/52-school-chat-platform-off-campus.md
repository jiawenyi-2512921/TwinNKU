# 学校对话平台校外不可达的排查

2026-10-01，用户反馈智能体一对话就超时。本文保留此前提交的服务器排查记录；后续代码复核补充证据边界，不把已有记录当作本轮重新执行的线上测试。

## 结论

**现有记录支持学校平台连接不可用是本次失败的主要线索。** 此前服务器侧探测 `coze.nankai.edu.cn` 的 80/443/8080 端口无响应，对话约 30.7 秒返回 503，与创建会话的 30 秒 socket 超时吻合。

访问策略调整、服务故障或针对该目标的网络过滤均可能产生此现象。仅凭端口静默和路由追踪不能确认学校策略变更，也不能彻底排除本站到该目标的网络问题；需要学校平台方确认。分阶段错误和日志改进见[54](54-agent-timeout-diagnostics.md)。

## 现象

此前提交记录称，以真实契约（`code` / `request_id` / `query` / `context`）实测三次对话，每次约 30.7 秒后返回 503：

```
[登录] HTTP 200  0.41s
[对话] HTTP 503  耗时 30.90s  问题: 图书馆怎么走
[对话] HTTP 503  耗时 30.67s  问题: 你好
[对话] HTTP 503  耗时 30.73s  问题: 介绍一下南开大学津南校区
```

返回体：

```json
{"error": {"code": "AGENT_UPSTREAM_UNAVAILABLE",
           "message": "学校平台响应超时，结果未确认，请勿立即重复发送"}}
```

## 定位

此前排查将超时定位到**第一步「创建对话」**。代码确认该步的 socket 超时为 30 秒，与记录相符；旧响应只包含通用上游错误，耗时本身不能独立证明失败阶段，后续应按54的分阶段日志复核：

```python
result = self.upstream(
    "create_conversation",
    {"UserID": session.user, "Inputs": {}, "ConversationName": "TwinNKU guide"},
    self.key,
    30,          # ← 与实测 30.7s 吻合
)
```

上游地址（`apps/api/app/integrations/nk_api.py`）：

```python
BASE_URL = "https://coze.nankai.edu.cn/api/proxy/api/v1"
```

超时被归类为 `NETWORK_TIMEOUT`：

```python
except urllib.error.URLError as error:
    if isinstance(error.reason, (TimeoutError, socket.timeout)):
        raise ProbeError("NETWORK_TIMEOUT") from None
```

## 证据

**此前网络记录**：DNS 正常解析；TCP 80 / 443 / 8080 全部无响应；连续 5 次探测均超时；curl 输出 `Trying <coze 地址>:443...` → `Connection timed out after 20001 milliseconds`。这些是当时、该出口的观测，不能证明所有校外网络均不可达。

**对照测试**：

| 目标 | 结果 |
| --- | --- |
| `www.nankai.edu.cn` | ✅ HTTP 200（1.1s） |
| **`coze.nankai.edu.cn`** | ❌ **超时** |
| `iam.nankai.edu.cn` | ✅ HTTP 200（0.7s） |
| `www.baidu.com` | ✅ HTTP 200（0.7s） |
| `dashscope.aliyuncs.com` | ✅ 可达（0.5s） |

`iam` 和其他公网目标可达，降低了服务器整体外网出口故障的可能性；仍需检查针对 `coze` 的目标路径、过滤和服务状态。

**此前路由追踪记录**：两个目标的探测包均获得末跳校内网设备响应；`iam` 的 443 正常响应，`coze` 的 80/443/8080 静默。路由追踪的响应不等同于 HTTPS 端到端可用。

**路由探测有响应、服务端口静默**支持继续排查目标服务及访问限制，但不能区分过滤、服务停机或策略变化。

## 候选原因与证据边界

| 假设 | 证据 | 结论 |
| --- | --- | --- |
| 近期问答代码回归 | 同期提交未修改 `assistant.py` / `nk_api.py` | 暂无此类回归证据，不代表排除所有既有缺陷 |
| 密钥失效 | 尚未得到上游 HTTP 401，旧演示同样超时 | 当前先排查连通性；恢复后仍须验证授权 |
| 服务器防火墙拦截 | 此前称 ufw 无针对目标的 deny/reject | 不能排除其他层或目标专属过滤 |
| 服务器整体外网故障 | 多个其他公网目标正常 | 可能性降低 |
| 网络抖动或持续故障 | 连续 5 次探测超时 | 当时持续失败，不能据此确认长期原因 |
| 目标链路过滤 | 路由探测有响应，HTTPS 不可达 | 仍待核实 |
| 学校侧访问策略变化或服务故障 | 目标端口静默、历史时通时不通 | 候选原因，需学校确认 |

## 历史可达性

此前记录显示部署出口在若干日期出现可达性变化，不能代表所有校外网络或当前服务状态：

| 时间 | 状态 |
| --- | --- |
| v0.8.0 时期 | 不可达 |
| v0.9.0（09-25） | 不可达（记录原文：从服务器侧完全不可达） |
| v1.0.2（09-28） | **可达**（HTTP 302 / API 返回 400，0.83s） |
| 本次（10-01） | 不可达 |

v1.0.2 的记录已注明"学校侧的网络策略可能已调整，或者当时是临时故障"。09-28 前后为短暂可达窗口。

## 依赖范围（不代替本轮线上验收）

| 功能 | 状态 | 说明 |
| --- | --- | --- |
| 智能体对话 | 此前记录失败，本轮未复测 | 依赖该上游 |
| 地图浏览 | 独立于问答链路 | 不依赖该上游 |
| 楼层 / VR / 视频 | 独立于问答链路 | 不依赖该上游 |
| 道路导航 | 独立于问答链路 | 不依赖该上游 |
| 语音合成 | 独立供应商 | 走百炼网关；问答失败时没有新回答可朗读 |
| 智能体登录 | 不访问学校问答接口 | 只验证本站访问口令；登录成功不表示上游已连通 |

## 处理建议

1. **与学校平台/网络维护方确认**服务状态及公网访问政策，提供测试时间、来源出口和失败请求编号；若确有白名单要求，再申请授权。此前可调用不代表永久获得访问权限。
2. 若平台确限校内访问，由部署方评估学校许可的网络接入方案；接入后仍需验收授权、会话及问答。
3. 若用户决定改接公网模型，另行实现适配、迁移所需知识并验证动作权限；不是换个地址即可立即恢复，本批不擅自更换问答模型。
4. **暂时关闭对话入口**（`chat_enabled`）。避免用户每次等待 30 秒才获得失败提示。

## 说明

对话失败提示「结果未确认，请勿立即重复发送」是准确且有意的设计 —— 上游可能已受理请求，劝阻重复提交可避免产生重复记录。本批已补充分阶段提示和按需诊断信息，见[54](54-agent-timeout-diagnostics.md)；这改善排查，不能恢复不可达的上游。
