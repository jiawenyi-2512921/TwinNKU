# NK-GeniOS：接口说明失效后的接入与访问排查

日期：2026-09-26。适用网站：https://2512921.cn 。本文件依据用户提供的发布页、嵌入代码及仓库实际实现；不依赖已失效的“接口说明”链接。本文不是学校后端API协议，不能据此拼装未经确认的请求。

## 1. 目前能确定什么

| 项目 | 已有证据 | 仍需确认 |
| --- | --- | --- |
| 网页SDK | 平台提供 `embedFull.js` / `HiagentWebSDK.WebClient`，参数为appKey、baseUrl、hideSidebar、variables | 网站访客的登录要求、校外网络、真实回答与引用 |
| 智能体API | 用户提供应用API密钥、APPID、base URL `https://coze.nankai.edu.cn/api/proxy/api/v1`；发布页显示运行中 | 准确method/path/headers/body/response、会话规则、应用授权范围 |
| 知识问答 | 用户在平台内用图书馆介绍成功回答一次 | 网站端的检索来源、后续追问及不同访客隔离 |
| 本站代码 | 已有SDK容器、公开配置、只读导览工具和知识导出 | 后端聊天适配器尚未实现，`capabilities.chat`仍为false |

SDK脚本加载成功、WebClient构造成功、平台能回答、校外访客能回答是四个不同验收项。某个执行环境返回502，不能单凭这一点断言学校强制SSO；发布页“运行中”也不证明匿名访问已开放。

## 2. 三种凭据不要混用

| 凭据 | 本项目用途 | 放置边界 |
| --- | --- | --- |
| WebSDK appKey | 平台嵌入代码的公开标识，不是后端API密钥 | 从服务器配置经公开web-config传给浏览器；仍不把实际值硬编码进仓库 |
| 智能体发布页API密钥与APPID | 未来由我们的服务器调用这个智能体，必须以官方协议和权限为准 | 密钥只在服务器环境或密钥管理设施；APPID不等同于鉴权 |
| 账号中心AccessKey ID/Secret、学校Cookie/JWT | 账号级权限或交互式登录态；不是本次网站共享账号方案 | 不复制到前端，不存GitHub，不转成公众聊天代理凭据 |

用户已经给过应用密钥，不需要再次粘贴。本文和代码都不记录该值。若真实密钥曾进入公开仓库、前端产物或公开截图，应在平台撤销并更换；仅删除当前文件不能撤回历史泄露。

“服务器调用AI、前端展示”是可以采用的架构，但前提是校方批准的应用API支持服务端调用及目标用户范围。它不能自动绕过学校网关、SSO、配额或使用政策。只反向代理学校登录页面、共享一个浏览器会话也不能提供可靠的多访客隔离。

## 3. 说明页没了，按什么顺序找证据

1. 回到智能体的“发布配置／概览”中的API行。若还有“调试”“请求示例”“导出”等入口，复制当前版本的示例；没有就跳过，不假设平台一定提供。
2. 若平台能导出当前实例的OpenAPI或提供与其版本匹配的官方SDK，保存去敏文件；核对它是“调用已发布智能体”的接口，不是我们网站的六工具插件规范，也不是另一个厂商版本。
3. 若只剩API密钥入口和base URL，请学校平台管理员提供最小调用示例及外部服务器接入要求。原失效链接、平台版本和发布渠道截图可帮助定位，但不包含密钥、Cookie或个人信息。
4. 浏览器Network面板可以辅助判断失败发生在哪一层；管理后台/预览页内部请求不自动等于可对外使用的稳定API。不要直接“复制为cURL”并公开，它可能携带学校Cookie、JWT和私人对话。内部请求需经平台确认后才作为服务端协议依据。

最小证据包应包含：

- HTTP方法、完整路径，以及必须的header名称；值使用占位符。
- APPID放在哪里、API密钥如何使用；不能预设为Bearer、HMAC或查询参数。
- 一轮普通非流式请求和成功响应，含正文与会话ID的实际字段。
- 同会话追问的请求；新访客是否必须另建会话。
- 认证失败、参数错误、配额超限的状态码与错误体；日志只保留脱敏分类和request ID。
- 若支持流式，再提供SSE事件与结束标志；首轮集成不必等流式支持。
- 适用平台版本、校外服务器网络要求、允许的用户范围和额度。

去敏后交给开发方；密钥由部署方在服务器单独配置。未取得以上材料前，不猜 `/chat/completions`、聊天链接slug、签名或模型名称。

## 4. 给学校管理员的问题

项目是在 `2512921.cn` 提供南开大学津南校区的公开校园导览。我们已发布“小开”智能体并取得应用API密钥和APPID，但“接口说明”页面失效。请协助确认：

1. 当前NK-GeniOS版本调用“已发布智能体”的官方请求/响应示例或替代文档地址是什么？
2. `api/proxy/api/v1` 是否允许校外服务器仅用应用凭据调用？是否需要校内网络、出口IP白名单或其他网关配置？
3. Web服务、WebSDK与API渠道的访问控制分别如何设置？允许公开匿名校园导览，还是仅面向持校内账号的用户？
4. 能否为本项目使用应用级最小权限凭据，避免账号级完整权限AccessKey？
5. 会话隔离、知识库引用、并发/调用配额、错误码和凭据到期规则是什么？

此清单不包含实际密钥。只有管理员确认可对公众开放后，才启用相应访客范围；不能用个人登录态代替该授权。

## 5. 同时可以推进的工作

### A. 先部署已经确认的Full SDK修复

按[32](32-nk-genios-web-release.md)检查最新完整提交CI，并同时重建API和web。保留现有环境、数据库、地图与楼层原图；不运行历史资源导入。

运行只读自检（输出路径须未存在，换成实际校区ID）：

```bash
python3 scripts/check_nk_genios.py \
  --base-url https://2512921.cn \
  --campus-id nku-jinnan \
  --expect-enabled \
  --check-sdk \
  --json-out var/nk-genios/access-check-20260926.json
```

脚本不需要学校API密钥，不发聊天请求，不输出appKey或原始响应。只证明执行机器能否读取相关公开资源；真实登录和问答仍为手工验收。不要为了自检关闭TLS校验、开放任意代理或全站取消CSP。

### B. 逐层判断“拉取失败”

| 观察结果 | 优先检查 | 不应推断 |
| --- | --- | --- |
| 本站配置仍为embedLite或INVALID_CONFIG | API/web是否同一修复版本，API容器是否已重建 | 不是学校账号错误的直接证据 |
| 学校脚本非JS、超时或5xx | 从部署服务器和实际用户网络分别测连接，保留状态/Content-Type/脱敏request ID | 不是所有环境都不可达的证明 |
| 明确跳转校内登录、401/403 | 具体渠道访问控制、网关规则、密钥作用域/有效期 | 不先假定加Cookie或换一把账号密钥即可 |
| 浏览器控制台明确CSP/CORS错误 | 实际违反的指令/域名，以及外层代理是否又加策略 | 不能靠全站通配符或关闭鉴权修复 |
| 已进入聊天但回答报错 | 平台模型服务、发布版本、知识库绑定、额度及真实错误码 | SDK初始化不等于模型调用成功 |

不要把学校密钥放在浏览器fetch中。正式服务端API集成会采用前端→本站后端→学校应用API，但只在协议和使用权限确认之后实现。

### C. 知识与平台配置照常推进

按[33](33-nk-genios-platform-setup.md)维护图书馆等已审核公开介绍、来源、版本和更新时间；从本站导出资料时只收录已发布内容。先以空variables测试，再建立十个变量并验证。六个只读工具需要从平台调试确认能访问我们的网站。

知识库、提示词、只读工具、评测数据与访问控制是不同工作项。完善知识不会解决SDK脚本或登录失败；同样，等待API协议不影响审核知识和准备评测。100题仍是待执行草案，不能填造命中率。

## 6. 后端API进入开发与上线的门槛

取得协议与访问授权后，按[24](24-agent-implementation.md)实现适配器和本地访客会话，再逐项验收：一次真实问答、一次同会话追问、两个访客不串话、真实引用/来源、限流/超时/错误与日志脱敏。应用凭据不发到浏览器，模型输出不直接执行地图或其他操作。

截至本次修复，没有使用用户API密钥请求学校接口，没有通过共享登录态接入，也没有连接或部署生产服务器。GitHub代码、CI通过、生产部署、学校问答与公众访问必须分开记录。
