# 产品范围与验收基线

## 1. 目标

Twin NKU 面向公众、校友、研学群体，帮助用户通过地图、问答、全景、楼层及讲解完成校园文化参观，帮助宣传部减少重复咨询、维护统一口径并发现知识缺口。

核心流程：提出需求 → 识别主题/模式/时间 → 选择审核点位 → 展示导览 → 打开素材并讲解 → 追问/跳过/缩短 → 回顾 → 必要时转官方申请渠道。

## 2. 用户与权限

| 角色 | 可以做什么 |
| --- | --- |
| 公众匿名访客 | 浏览公开已发布资料；在建立匿名会话后问答与导览 |
| 获授权访客 | 除公开资料外，访问分配范围内的受限素材；不能由模型授予权限 |
| 编辑 contributor | 整理点位、上传素材、提交审核；不能直接发布 |
| 审核 reviewer | 审核、退回、发布、撤回内容；必须留痕 |
| 运营 analyst | 查看脱敏统计、知识缺口；不能读全部原始咨询或改权限 |
| 管理员 admin | 管理角色、系统配置与紧急撤回；最小授权 |

生产可暂时只开放匿名公开内容。未实现身份模块前，不发布受限素材，也不以隐藏按钮代替服务端授权。

## 3. 三种产品状态

1. 基础站：真实前后端、空内容状态、部署与监测完整。
2. 可演示版：代表点位、三条主题导览、真实智能体调用、少量楼层样板、基础内容维护。
3. 部门试用版：材料审核人、更新周期、真实用户反馈、分流与统计、权限验证。

“前后端上线”不能等同“产品全部完成”；每个模块独立验收与启用。

## 4. 首版范围

| 能力 | 交付边界 | 明确排除 |
| --- | --- | --- |
| 地图 | 修订规划图、建筑点击、检索、缩放、路线高亮 | 重新生成全校建筑、双底图切换、实时 GPS |
| 导览 | 线上主题顺序、线下核实路网、途中调整 | 以规划图推断所有道路可走 |
| 问答 | 有依据讲解、追问、无依据分流 | 自行编造校史、政策、入口、营业时间 |
| VR | 已核实公开场景入口；平台允许时嵌入 | 未验证即承诺视角控制、反向读取场景 |
| 楼层 | 获准公开楼层查看；一栋两层导航样板 | 根据消防图自动推断门或电梯可用 |
| 语音 | 审核讲解稿的音频、文字稿、暂停和停止 | 首版依赖全天候语音识别或数字人 |
| 管理 | 内容审核、素材分级、问题归集、渠道配置 | 自建学校预约审批系统 |

## 5. 线上与线下

- `virtual`：按文化主题组织点位；估时来自音视频及阅读时长，不产生步行距离。
- `walking`：经过真实道路和可用入口；先过滤访问权限、关闭边、时段，再算最短路。相邻景点不可达时明确提示。
- 线下建议不授予入校资格；预约与访问政策来自有效审核资料。
- 没有可靠无障碍路网，不显示“无障碍可达”承诺。可声明数据不足。
- 无实时定位，起点来自用户选择；“到达”需用户操作或可信平台事件，不自行宣称。

## 6. 代表性验收场景

| 场景 | 预期结果 |
| --- | --- |
| 20 分钟线上校史参观 | 返回点位顺序、估计内容时长和资料来源；可缩短并继续 |
| 指定两个建筑间步行 | 返回有图版本的路径分段；没有核实路网则不画直线冒充路线 |
| 当前正在看图书馆，追问“这里有什么” | 请求携带当前点位上下文，回答不跳到其他建筑 |
| 打开没有全景的点位 | 显示暂无全景，可继续阅读资料 |
| 询问未知参观政策 | 标明缺少有效依据，提供经核实官方渠道 |
| 请求内部未公开楼层 | 后端拒绝，模型不返回图片地址或内部摘要 |
| 内容撤回 | 页面不再公开，知识库/缓存同步失效，旧会话不重新复述该内容 |
| 外部 AI 服务不可用 | 地图和已审核资料仍能浏览；聊天明确显示暂不可用 |

## 7. 试用目标（不是已取得成绩）

首批 15—20 个审核点位，覆盖主要类别；3 条主题导览；2 栋楼可查看内部，1 栋楼验证两层路线。建立不少于 100 个评测问题，记录事实正确性、来源对应、拒绝/分流、完成率和耗时。

由宣传部指定人员确定官方讲解、政策和公开范围；目前材料处于预计可获得状态。没有部门审核的演示资料必须明确标记，不宣称已经成为官方服务。

## 当前实施重点（2026-09-23）

先按用户反馈完成可点击建筑、去序号和可读名称，再用5个有真实材料的点位跑通一条线上主题导览与上下文问答。楼层图持续作为建筑详情资料接入，不把全校室内导航作为当前主线。已运行的是地图与楼层基础；AI、VR与主题导览仍未实现，不能把素材数量当作导览服务已完成。详见[当前目标与地图改版](13-map-interaction-update.md)。
