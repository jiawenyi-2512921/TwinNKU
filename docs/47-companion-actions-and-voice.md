# 随行角色、直接操作与语音配置

更新：2026-09-29。接续 `feat/admin-console` 的 `e9fcf0e`。本文区分本批代码与待接入的云语音，不代表已经部署。

## 交互目标与本批范围

小开使用轻量 SVG 角色呈现，会话仍沿用本站原生学校 API。角色状态来自实际聆听、等待、朗读和动作核验；平时展示字幕与少量控制，文字历史按需展开。无需下载 Live2D、3D 引擎或本地模型；减少动态效果偏好会停用角色动画。

用户明确要求定位、打开已标注楼层、查看路线、开启校园导览、查看打卡或播放视频时，由服务器判断执行意图，再核验真实已发布目标。`GuideReply.automatic_action_id` 只标记唯一明确动作，前端再调用现有 `/agent/actions/resolve`，检查上下文和资料版本。普通咨询、否定、歧义和多候选不自动执行；旧 API 未返回该字段也不自动执行。后台 `auto_actions` 与动作白名单继续有效。

- 本站操作保留对话与随行角色。打开路线规划不等于路线已计算成功；结果由导航模块实际返回。
- 明确播放视频可直接进入播放器并尝试播放；浏览器拒绝有声自动播放时显示播放按钮。普通浏览和推荐仍由用户决定观看，不把 URL 参数作为播放授权。
- VR只打开已发布的HTTPS原站链接，语音/异步动作可能被浏览器拦截，届时保留一次点击的核验链接。不会恢复iframe或把本站自动替换成外站。返回本站可继续导览，不能在学校原网站注入小开。
- 小开只能调用本站已经实现、允许且已发布的功能；不能凭模型文字执行任意代码、凭空生成校园资料、自动审核发布或修改管理数据。

## 现在怎样使用语音

当前仍是浏览器 `SpeechRecognition` 和 `speechSynthesis`：用户点击开始语音、允许麦克风；说完一句交给学校 API，回答后朗读并继续聆听。不需要另填语音服务商密钥。浏览器支持度、系统可用音色和语音识别网络条件会影响使用；不支持时保留文字交流。这不是云语音已接入，也不是全双工实时语音。

当前 `voice.ts` 支持按钮打断朗读；尚不支持朗读时持续识别用户插话。切到后台、关闭交流或播放视频时暂停语音。学校 API 仍等待完整文本回答，因此单换音色不能消除学校回复耗时。

## 推荐的云语音配置准备

建议先用阿里云百炼提供语音识别（ASR）和语音合成（TTS），学校 NK-GeniOS 继续负责校园问答与动作。以下为根据2026-09-29官方文档选择的一组起步配置，并非跨设备延迟或音质实测排名。

| 配置项 | 起步选择 | 用途 |
| --- | --- | --- |
| 地域 | 华北2（北京） | API Key、模型和接入地址保持同地域 |
| ASR模型 | `paraformer-realtime-v2` | 语音流转文字；校园名称可配置热词 |
| TTS模型 | `cosyvoice-v3-flash` | 将学校回答合成为音频 |
| TTS音色 | 先试听 `longanyang` 或官方列表内同版本中文音色 | 系统音色即可开始，不必先做声音克隆 |
| 凭据 | 百炼 API Key | 与学校智能体应用密钥分别保管 |
| 业务空间与地址 | 从所选地域控制台/官方接入信息取得 | 不把文本模型的 OpenAI-compatible URL 当作语音 WebSocket 地址 |

开通步骤：

1. 登录阿里云百炼，完成平台要求的服务开通，在 API Key 页选择北京地域；确认该业务空间可调用所选 ASR/TTS 模型。
2. 为项目创建 API Key。保存地域、业务空间 ID、模型名称和音色 ID。长期密钥只交给部署人员保存在服务器的受限环境/密钥文件，不发到聊天、前端 `VITE_*`、GitHub 或日志。
3. 用官方音色列表试听声音，先选普通话系统音色。语速和音量先保持默认，在实际手机与电脑听过后调整。
4. 接入适配器后，由部署人员注入服务器配置并启动服务，分别验收识别、合成、学校问答和动作结果。不要把服务商控制台试听成功算成网站已经接通。

**当前仓库尚未实现百炼音频适配器。** `DASHSCOPE_API_KEY` 是官方 SDK 的环境变量名，当前 Twin NKU API/Compose 不会读取并启用它；不能仅在现有 `.env` 添加这个变量就得到云语音。本批不增加虚假的语音配置按钮或未实现的生产端点。

官方文档现有北京示例的 WebSocket 地址为 `wss://{WorkspaceId}.cn-beijing.maas.aliyuncs.com/api-ws/v1/inference`，其中业务空间 ID 需要实际替换。接入时必须重新核对所选模型/协议的地域信息，不混用新加坡密钥、HTTP聊天地址或其它语音厂商的AppID。

## 后续接入工作

音频链路计划为“浏览器麦克风→本站音频会话→百炼ASR→现有学校问答/动作核验→百炼TTS→浏览器播放”。不替换学校智能体，不让供应商长期密钥出现在浏览器。

接入时实现有会话鉴权和限额的同源音频通道、音频格式转换、流式字幕、断线/取消清理与音频播放队列；给“正在聆听/等待学校回复/朗读/动作失败”分别提供真实状态。首阶段验证轮流交互，之后再做回声消除、语音打断和弱网恢复。不能把ASR连续出字称为整条学校问答已经端到端流式。

真实验收至少覆盖：麦克风拒绝、不支持的浏览器、校园专名、否定命令、多候选、用户中途换地点、资料下架、VR弹窗拦截、视频拒播、页面退到后台和长回答取消。记录识别终点、学校首个回复、声音首帧及动作结果分别耗时；不承诺未测的毫秒数。
