## 3. 部署前检查

1. 进入现有项目目录，确认没有未提交的部署方修改；记录当前`git rev-parse HEAD`和web镜像ID。若有本地改动先保留并审阅，不强制reset覆盖。
2. 确认站点已有0005后端、楼层/VR正常，以及当前数据库/素材备份可用。
3. 拉取目标分支，确认GitHub最终提交与CI；后续步骤只更新web。旧系统未到0005则按18完整升级，不跳迁移。
4. 不重新导入校园地图，不用旧种子覆盖后台几何，不运行清卷/重建数据命令。

```bash
git fetch origin
git switch feat/admin-console
git pull --ff-only origin feat/admin-console
git rev-parse HEAD
docker compose build web
docker compose up -d --no-deps web
docker compose ps web
```

若fast-forward失败，先查本地提交差异再处理，不强制覆盖。HTTPS入口和站点配置沿用原有设置；无需在本轮修改防火墙/SSH/API key。
