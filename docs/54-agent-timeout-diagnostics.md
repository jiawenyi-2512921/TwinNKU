# 智能体超时：分阶段诊断与恢复

2026-10-01，接续 `feat/admin-console` 的 `5c05891`。用户反馈智能体持续超时；本批核对最新[服务器排查记录](52-school-chat-platform-off-campus.md)，补充代码诊断，不替代学校服务或真实设备验收。

## 当前最有依据的判断

此前提交记录中的三次对话均约 30.7 秒返回 HTTP 503，学校目标端口探测失败。代码确认首轮先调用 `create_conversation`，其 socket 超时为 30 秒，因此学校连接不可用是主要线索。登录只验证本站口令，不验证学校连通性。

旧错误只返回 `AGENT_UPSTREAM_UNAVAILABLE`；约 30 秒的总耗时不能单独证明失败阶段。访问策略、平台停机、目标路径过滤等均待平台/网络维护方确认，本批纠正52和文档入口中“学校策略变更已确认”的过强结论。

本轮只读 GET 本站 `/health/live` 和学校公开首页，均在执行环境的代理 CONNECT 阶段失败，没有得到目标 HTTP 响应。网页检索工具也不可读取这两个页面。这说明本轮不能从当前环境复测生产状态，不能据此断言用户服务器或学校现在宕机。没有登录服务器、使用密钥或调用真实问答。

## 本批行为

- 创建会话超时返回 `AGENT_CONVERSATION_TIMEOUT`，回答超时返回 `AGENT_REPLY_TIMEOUT`；网络/TLS/传输失败返回 `AGENT_UPSTREAM_CONNECTION_FAILED`。固定提示说明失败阶段、结果未确认及不要立即重复发送，不猜测学校政策。
- 后端分别记录创建会话和回答的阶段、耗时、白名单错误分类以及本站请求编号。编号与错误响应的 `meta.request_id` / `X-Request-ID` 对应，不记录提问、回答、密钥、用户标识、会话标识或上游异常原文。
- 网页保留安全错误码与 UUID 编号，放在展开的文字记录中按需查看；默认角色旁字幕只显示简短错误。无 JSON 的 HTTP 504 明确提示网站代理等待超时。
- 网页真正限制包括响应体解析在内的总等待，仍为 105 秒；用户主动取消与等待超时分别提示。取消只结束网页等待，不能保证已送到上游的请求取消。

无自动重试，不把失败变成模拟回答，不切换问答模型、Cherry 音色、语音限额或资料动作权限。再次手动发送会创建新请求；恢复连通前反复发送不能修复网络，还可能产生重复调用。

## 等待预算

| 层次 | 当前设置 | 含义 |
| --- | --- | --- |
| 创建学校会话 | 30 秒 | urllib socket 操作超时 |
| 学校回答 | 60 秒 | blocking 请求的 socket 操作超时 |
| 网页问答 | 105 秒 | 包括响应体解析的总等待截止 |
| 仓库 Nginx | 120 秒 | 代理读取间隔超时 |

首轮依次创建会话、请求答案；后续复用会话。socket/代理超时不等于整个事务硬截止，不能宣称后端首轮严格不超过 90 秒。仓库默认值没有明显倒挂；服务器外层代理实际配置仍待部署方复核。本批不统一加长等待。

## 部署与复核

本批修改 API 和 web，无新增依赖、DTO、OpenAPI 字段或数据库迁移。由用户/部署方拉取开发分支后配套重建 API/web；不要只更新 web，否则阶段码和日志仍是旧版。API 重建会清除进程内访客会话、语音缓存和限流计数，需要重新登录；不修改生产内容或地图资源。

1. 在文字交流记录里展开失败条目的诊断信息，记录错误码、请求编号、失败时间和 Network 面板中的 HTTP 状态/耗时。不要提供口令、Cookie、API Key 或请求正文。
2. 部署方用同一编号查 API 日志：`stage=create_conversation` 失败表示尚未进入回答阶段；创建成功后 `stage=chat_query_v2` 失败表示回答阶段失败。`reason=NETWORK_TIMEOUT` 仍可能涉及连接或读取，不能直接认定模型生成慢。
3. 若网页显示代理 504 而未收到 API 编号，查外层代理与本站 Nginx 的对应日志/实际等待设置；不能用仓库120秒证明生产外层配置。
4. 在部署网络检查学校 HTTPS 可达性，并与学校维护方确认服务及授权公网访问范围；如确限白名单，按学校要求申请。学校恢复后再做一次真实会话和回答验收，不连续重复提问。
5. 若学校连接短期无法恢复，可由管理员暂时关闭问答；地图、楼层、VR、导航使用独立链路。改接公网模型需用户明确决定并另做适配、知识迁移与动作验收，本批不擅自更换。

## 验证与下一步

自动测试验证阶段分类、日志脱敏、请求幂等/资源释放，以及网页错误编号、总等待和取消；具体执行结果写入 `VALIDATION.md`，提交和 CI 单独核对。模拟上游测试不证明学校恢复，构建不证明用户设备实际表现。

下一步是部署方核对一次失败请求的编号与阶段，并向学校确认连接原因。若学校回答阶段恢复可达但仍慢，再基于真实耗时评估资料预算及官方支持的流式协议；不从耗时猜测协议，不为了掩盖连接故障增加超时。
