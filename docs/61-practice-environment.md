# 独立内容练习环境

本文件说明候选版本的练习环境部署与边界。它用于学习内容编辑、预览、提审、独立审核、导入和历史找回。当前只有代码及相应检查通过的项目可视为已验证；练习素材、完整环境启动、真实人员任务和重置演练仍须记录实际结果。不能把部署定义或单元测试当作培训已经完成。

## 隔离方式

- 独立 `compose.practice.yaml`，项目固定为 `twinnku-practice`，不能与生产 Compose 文件合并。
- 新建 `twinnku_practice` PostgreSQL 数据库，迁移使用 `practice_owner`，在线使用降权后的 `practice_runtime`。口令随机生成，不读取生产 `.env`。
- 地图、媒体与数据库使用本项目独立具名卷，不挂载主机素材路径、外部卷或生产卷。
- 数据库、迁移和 API 只连接独立的内部 Docker 网络，没有供应商出站网络。web 额外连接本练习项目专属的入口桥接网络，端口仍只绑定主机 `127.0.0.1`；数据库和 API 不发布端口，也不能加入入口网络。web 不持有供应商或数据库凭据，其固定代理只通向本练习 API。
- 应用明确设置 `PRACTICE_MODE=true`。服务端启动时拒绝供应商密钥、问答或合成开关、非练习数据库和不匹配的本机来源。
- `/api/v1/system/status` 返回 `environment=practice`，界面依据此结果显示练习提示，不依据网址猜测。员工 cookie 使用独立的 `twinnku_practice_` 名称。
- 保存、审核和发布仍使用真实服务端权限、范围、贡献者和版本规则。用不同练习账号完成编辑和独立审核，不自动代审。

生产保持原固定域名 WebAuthn 规则。此本机内容练习栈不绑定正式认证器，也不声称验证了生产 MFA。主、备用认证器和恢复流程在正式验收环境由实际人员完成。真实声音生成与实时问答另在有批准预算的验收环境测试；练习站不能通过后台策略开启它们。

练习站的通行密钥使用独立的 `localhost` RP ID 和已配置的准确本机 Origin（包含端口）。只有完整隔离配置验证通过的 `PRACTICE_MODE` 才能使用该范围；登记、登录签名验证及用户设备验证仍全部执行，范围不从请求 Host／Origin 头生成。普通环境继续固定 `2512921.cn`／`https://2512921.cn`。成员应在自己的设备上给练习站单独绑定认证器；真实设备步骤不由自动化代做。该范围修复的 staff/practice 组合107项通过，1项既有Windows POSIX文件权限检查跳过；包含真实P-256签名、错误域名、错误端口和缺少用户验证的拒绝用例。

## 准备与启动

在 Linux Docker 主机操作。三个候选镜像先完成构建及安全检查，使用各自完整的本地 `sha256:` 镜像 ID；维护脚本不拉取镜像。API、web、数据库分别要求已审的非 root 运行用户。

从仓库根目录运行下列命令，将大写占位符替换为实际已验证的镜像 ID：

```sh
python3 scripts/practice_environment.py init \
  --directory /opt/twinnku-practice-private \
  --api-image API_IMAGE_ID \
  --web-image WEB_IMAGE_ID \
  --db-image DB_IMAGE_ID \
  --port 8098
python3 scripts/practice_environment.py verify --directory /opt/twinnku-practice-private
python3 scripts/practice_environment.py up --directory /opt/twinnku-practice-private
```

初始化目录必须不存在，创建为0700；口令文件与环境身份记录为0600。初始化不会启动服务，也不会创建员工账号或导入生产内容。`verify` 校验实际 Compose 解析结果、镜像身份、内部与入口网络分工、本机绑定、独立卷和现有 Docker 对象归属；运行后的 web 还须核对 `NetworkSettings.Ports`，不能仅凭声明了端口就认定入口可访问。任何冲突都停止操作。

入口网络用于兼容 Docker 对仅连接内部网络的容器可能不实际发布端口的行为。已有候选实测 API 与内部网页代理均返回200、本机入口却无法连接；同类行为见 [Moby 上游记录](https://github.com/moby/moby/discussions/53256)。修订后的拓扑仍须真实启动、HTTP流程及重置验收通过，不以 Compose 校验代替。

`up` 只启动练习服务并执行本环境迁移及在线角色降权，随后读取 API 的真实环境标识。若标识不符或问答能力意外开启，停止本练习栈。旧版不支持练习边界的镜像不能作为验收候选。

启动成功后在运行 Docker 的电脑访问 `http://localhost:8098`。服务器部署时，通过经批准的 SSH 本机端口转发访问；不要改成公网监听以便培训。访问地址、端口、Origin 必须一致。

## 账号和素材准备

使用本练习项目的 `app.modules.admin.bootstrap` 交互式命令创建首位练习管理员，密码由维护人员在终端输入，不写到命令参数、日志或操作手册。管理员再创建独立练习编辑和审核账号，按练习校区分配范围。不得导入生产员工、会话、认证器、恢复码或审计身份。

素材初始化是独立步骤：使用明确标注的练习资料或有权使用的公开素材，通过本环境导入流程形成草稿。未准备素材时显示空状态，不能把空站点作为完成的六步路线示范。练习站发布仅影响练习站。

练习中可完成图文路线和内容审核。音频练习仅使用明确标注、与固定练习稿精确匹配的预置声音，训练试听、采用及改稿后的失效处理；改稿后没有匹配声音时禁止沿用旧声音。收费生成入口说明停用原因，不伪造新生成结果。真实生成、重生成及费用故障恢复另在专用凭据和批准预算的隔离验收环境完成，不能把浏览器朗读当成供应商合成验收。完整任务证据仍按最终方案第15.4节记录。

## 停止与重置

停止保留练习数据：

```sh
python3 scripts/practice_environment.py stop --directory /opt/twinnku-practice-private
```

以下显式重置会删除本练习栈的练习数据库与素材卷，操作前先导出需要保留的练习稿：

```sh
python3 scripts/practice_environment.py reset \
  --directory /opt/twinnku-practice-private --confirm-reset
```

重置保留私有部署配置，之后可重新启动并准备练习账号和素材。脚本先核对现有容器、网络和卷的项目及练习用途标签，包括停止的容器和同名但无标签的对象；无法确认归属就拒绝，不按名称模糊删除。此命令不调用生产项目的 Compose，也不删除主机目录。

## 必须留存的验收证据

记录候选镜像 ID、Compose 和源码版本、真实环境标识、数据库角色检查、资源归属、没有公网端口、API/数据库无外网连接、只有web连接专属入口桥、没有供应商凭据、内容编辑与独立审核结果、响应未知后的操作查询、重置前后数据以及生产仍正常的检查。练习生成不得产生供应商尝试或费用计数。

随后由至少三位未参与开发的人员实际完成任务；操作截图和短视频来自最终界面。内容练习、生产认证、真实供应商、真机视觉和完整恢复分别验收。
