# 地图加载、性能与故障验收

更新日期：2026-09-29。接续 `feat/admin-console` 的 `c8363a6`，保留该提交的产品文案修正。用户反馈电脑打开地图常失败、交互不够流畅。本次先修有代码证据的问题，智能体新形态的研究见 [46](46-companion-interaction-research.md)。

## 已核对的事实

- 一次线上浏览器检查成功展示了校园地图，当前视区6张图块均完成加载。没有重现用户电脑的失败，因此不能称生产问题已完全解决。
- 本次执行环境对首页、状态与地图列表的少量匿名GET均返回200，分别约9.45、6.79、6.95秒。这是当前执行环境的端到端样本，包含网络连接等等待，不能据此证明用户设备、服务器CPU或SQL耗时。
- 原首页地图列表响应为42,986字节，包含大量楼层地图元数据；首页只需要校园底图。原JSON与瓦片均为 `Cache-Control: no-store`。
- 前端任意一张图块触发错误后，告警不会因成功或离开视区消除；手动重试调用整层 `redraw()`，会重新请求正常图块。
- 未显示路线时，App每次渲染创建新的空路线数组。选中地点的自动定位effect依赖该数组，导致搜索、帮助或背景刷新等无关渲染再次定位，干扰用户刚拖动的视角。该问题通过执行实际组件源码的受控测试复现。

服务器占用低不能排除公网带宽、DNS/TLS、代理、浏览器下载队列、图片解码或前端状态问题。本补丁没有为服务器瓶颈下结论，也没有登录服务器。

## 本次修复

### 图块恢复与地图视角

图块按实际视区和加载生命周期管理。短暂失败或挂起只对相应图块进行有界恢复；正常图块不因一次失败而整层重取。成功、离开视区和卸载清理告警、监听器与计时器。手动重试保留当前位置与缩放。

无路线时复用稳定的空数组；选点定位以是否有路线为条件，避免无关渲染反复拉回视角。真实地图版本更新、切换地点或路线变化仍按原业务逻辑处理。

### 请求与传输

- 首页不再等待仅用于预判的全系统状态查询；公开地图接口本身继续强制执行模块开关与发布校验。
- 地图列表支持可选 `kind=campus|floor`，省略参数仍返回原有结果。首页只请求校园底图，地点列表并行读取，取得地图ID后立即读几何。旧API忽略额外查询参数时仍可被前端过滤，但应配套更新API以减少响应体。
- 版本化瓦片允许浏览器保存字节，每次复用前仍向API核验：`private, no-cache`、ETag、`If-None-Match`/304。授权、公开状态、当前版本、坐标范围与文件存在检查均先于304；下架或错误响应仍 `no-store`。不使用会跳过下架检查的长时间公开瓦片缓存。
- Nginx为文本资源启用gzip，哈希命名的JS/CSS可长期缓存；入口HTML重新校验。PNG、视频不重复gzip。API资料、后台、会话与错误响应不套用静态资源缓存，原安全头保留。

本次不更改地图/楼层原图字节、图块、校准坐标、路网、内容发布状态、数据库结构或学校API协议。

## 部署

本补丁包含API和web，需配套更新；无新增数据库迁移。已完成上一批 `0008_campus_tours` 的部署方，在现有项目目录拉取最终完整提交、确认CI通过后执行：

```bash
docker compose build api web
docker compose up -d --no-deps api web
python3 scripts/smoke.py http://127.0.0.1:8080
```

保留现有环境配置、Compose项目名与数据卷；不重新导入地图，不运行旧seed。不在0007或更早的数据库上只替换新镜像；旧版本先按 [44](44-vr-campus-tours-editor.md) 完成既有升级。本次未执行生产上线、迁移、审核或发布。

如果站点前面还有服务器宿主机的Nginx/CDN，必须在公网入口核对实际返回头。仓库内Nginx通过不代表外层代理没有覆盖缓存、压缩或连接配置。不要直接将整个 `/api/` 设为长期公开缓存。

## 从出现问题的设备收集证据

新工具仅做少量匿名GET，检测首页、一个前端脚本、公开校园地图目录、一个版本图块及一次条件读取，不下载整校楼层或整张地图：

```bash
python3 scripts/check_map_delivery.py --base-url https://2512921.cn --json-out map-delivery.json
```

加 `--strict` 可将未启用gzip、哈希缓存或瓦片重新校验策略视为验收失败；CI在真实Compose网页容器中使用严格模式。没有已发布校园地图时明确跳过图块抽样，不算地图内容已验收。默认最多6个请求、单请求8秒、总预算45秒；需要检查较慢链路时可明确调整 `--timeout` 与 `--max-seconds`，不要把提高超时当作性能修复。

可分别在出问题的电脑网络与服务器本机执行，比较响应状态、耗时、传输字节、gzip、缓存头及304行为。报告不包含Cookie、授权头或问答内容；这不是压测，也不能测量浏览器FPS、内存、图片解码和实际首屏。

同时在电脑浏览器开发者工具中保留一次失败记录：失败的是首页JS、地图目录/几何还是PNG；记录状态码、请求耗时和 `X-Request-ID`。若记录HAR，分享前删除Cookie、Authorization与个人问答内容。不要以反复刷新成功一次替代故障定位。

## 验收与后续门槛

1. 当前图块全部成功时没有失败告警；模拟一个图块失败只恢复该图块，已成功图块不被整层重取；挂起有明确恢复入口。
2. 拖动地图后，目录刷新、展开帮助或输入检索不会将视角拉回已选地点；切换地点与开始真实路线仍正常定位。
3. 同一版本图块再次读取能使用条件请求；地图下架、停用、版本变更、缺失图块不能继续返回304或200。
4. 首页只取校园地图元数据；发布、撤回与恢复前台后的公开资料同步仍有效。
5. 公网脚本返回gzip与哈希缓存策略；入口HTML不被长期固定在旧版本。
6. 由团队在目标电脑与iPhone上各做冷启动、热启动、缩放拖动和弱网恢复验收，记录网络、浏览器、次数与真实耗时。自动测试、构建和CI分别记录在 `VALIDATION.md`，不能冒充这些设备结果。
