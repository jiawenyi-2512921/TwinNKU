# 语音首句与随行字幕优化

2026-09-30，接续开发分支 `feat/admin-console` 的 `6064421`。用户反馈语音响应慢、字幕位置奇怪；本批保留已接入的 Qwen TTS、Cherry 音色、学校问答及后台动作核验。

## 定位与改动

现有问答等待学校返回完整答案，云语音再等待完整 WAV。前端原先把不足300字的回答整体合成，较长回答则逐段“合成→播放完→再合成”，会让首句等待长文本，并在段落间重复等待。字幕原先独立固定在屏幕底部，手机/矮屏固定顶部，没有跟随可拖动的小开。

本批优化前端播放编排：不超过80字的短回答保持一次合成；较长回答先按自然句界合成最多80字的首段，后续保持每段最多300字；切点不拆开emoji。当前音频真实开始播放后，只预取下一段。窗口始终只有一段，不批量合成整篇。拒播期间不继续预取；继续播放沿用已经合成的同一份音频。预取失败不打断当前声音，当前片段结束后才按原有规则降级未播放的文本。

取消、关闭、后台、视频与新对话会中止前端当前/预取请求，清理播放器等待并丢弃旧结果。浏览器取消不能保证供应商已经收到的收费请求停止。每段仍遵守现有长度和服务限额；首段拆分可能多一次合成，后续不全部切成小段，也不自动提高额度。

字幕改为小开旁的气泡，随拖动移动；根据角色、字幕尺寸和可见视口选择位置并保持在屏幕内。窄屏、横屏和屏幕键盘变化时重新定位；较长字幕可滚动。文字抽屉展开时仍隐藏浮动字幕。等待问答和合成时显示对应真实阶段，错误/拒播提示仍优先，不用上一句字幕冒充正在播放。

这是短首段和有限预取，**不是学校回答流式化、云ASR、全双工或带词级时间戳的音频**。不能根据构建、受控播放事件或 CI 声称线上延迟减少了多少秒。

## 更新与真实验收

本批只更新并重建 **web**。已经完成49配套更新的API无需因此重建；较旧部署先按[49](49-cloud-voice-playback-fix.md)核对版本和语音配置。没有新增依赖、数据库迁移、权限变化、地图坐标或图像字节修改，不自动部署服务器。

在目标电脑和手机记录以下真实结果：

| 场景 | 需要确认的行为 |
| --- | --- |
| 语音或文字提问、较长回答 | 首段请求是短句；首段播放期间仅请求下一段，后续不等待上一段结束才开始请求 |
| 浏览器拒绝自动播放 | 播放图标与提示可见；点图标恢复同一份音频，拒播期间没有继续预取 |
| 第一段播报时关闭/切后台/打开视频/新对话 | 声音停止，预取结果不会迟到播放；供应商已收到的请求是否计费由供应商决定 |
| 第二段合成失败 | 第一段正常结束，不被提前打断；仅未播放文本降级，不重新读第一段 |
| 小开四边拖动、窄屏、横屏、键盘打开 | 字幕在小开附近且处于可见区域，可滚动，不遮住角色主要操作；展开抽屉不出现第二份字幕 |
| 问答等待、合成等待、真实播放 | 阶段提示对应当前状态，不显示上一轮内容作为新一轮字幕 |

浏览器 Network 分别记录 `/agent/chat` 与 `/voice/speech` 的请求开始、首字节和完成时间，再记录实际音频开始；首轮创建学校会话与学校完整回答也会造成等待。API已有 `X-Request-ID` 与服务端 `duration_ms` 日志可用于对应核查，反馈不要包含密钥、会话口令、Cookie或供应商签名音频网址。不把服务器 CPU 低当作网络或供应商响应正常的证据。
